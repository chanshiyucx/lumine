# 地图选中相册跨缩放保持可见

- 状态：已实施，核心交互已完成浏览器回归
- 日期：2026-09-25
- 范围：地图聚合、选中相册标记和预览卡

## 问题

地图用 `pinnedAlbumKey` 记录用户点击的相册，并通过该相册的标记显示预览卡。缩放结束后，Supercluster 会按新视口重新生成标记。如果已选相册并入聚合，原标记卸载，预览卡随之消失，但 `pinnedAlbumKey` 仍保留。用户放大回原级别时，卡片可能再次出现。选中状态和可见内容因此不一致。

## 目标与交互

1. 选中相册后缩小、放大或平移地图，选中标记始终作为独立标记绘制，预览卡保持与它关联。
2. 其余相册照常聚合；聚合数量和叶子列表不包含已选相册，避免同一相册同时出现在独立标记与聚合里。
3. 点击已选标记、地图空白处、聚合标记或地图范围按钮时，继续按原交互取消选中。取消后，该相册立即回到正常聚合。
4. 普通标记与聚合标记的悬停预览、封面加载规则保持现状。

## 实现方案

`prepareAlbumMapSelection(items, pinnedAlbumKey)` 从当前相册集合中查找选中项，并用其余相册建立 Supercluster 索引。若传入的 key 已不在集合中，则视为无选中项，全部相册进入索引。

`AlbumMap` 只在 `items` 或 `pinnedAlbumKey` 变化时重建索引；地图移动导致的视口更新继续用同一索引调用 `getClusters()`。聚合标记正常渲染，选中标记在其后单独渲染，以保持可见和可交互。

普通标记与选中标记必须处于同一个扁平的 React 子节点数组，并沿用相册 key。点击固定或取消固定时，React 才能复用同一个 `AlbumMarker` 和 MapLibre 标记；拆成两个 JSX 子节点槽位会使标记卸载重挂载，并让卡片重新播放入场动画。若取消固定后该相册本来应进入聚合，标记消失仍是预期行为。

选中卡片继续使用现有 Radix Portal 以保留视口边缘的碰撞处理。地图动画通过 CSS transform 移动标记，因此仅在卡片固定时启用 Radix 的逐帧位置更新，并在标记离开可视区域时隐藏卡片。普通悬停预览继续使用默认的按需定位策略。固定卡片离开视口后，逐帧位置检查仍会持续；同一时刻最多只有一张固定卡片，后续若性能记录显示开销明显，再考虑视口外暂停定位。

点击选中标记会取消固定；点击空白处、聚合标记或范围按钮也会清空 `pinnedAlbumKey`。这些动作触发一次索引重建，原选中相册重新参与聚合。首次地图定位仍使用完整相册集合，避免选中状态影响“聚焦主要区域”的判断。

## 验收与验证

- 在相邻位置放置至少三个相册：选中其中一个后缩小地图，确认选中标记与卡片仍可见，聚合数字只计算其余相册。
- 连续放大、缩小并平移地图，确认没有重复标记，卡片跟随其标记；点击空白处和聚合标记后卡片关闭，原相册重新进入聚合。
- 在已选相册从 `items` 中消失时，确认不会遗留独立标记，也不会遗漏其他相册。
- 自动化验证使用真实 Supercluster 索引检查选中项分离、缩放前后的聚合计数和失效 key 回退。

本次已通过两项聚合行为测试、`pnpm type-check`、修改文件的 ESLint 和 Prettier 检查，以及 `git diff --check`。类型检查运行于 Node 22.23.2，低于项目声明的 Node 24 最低版本；该环境提示不影响本次检查结果，但仍应由符合版本要求的 CI 覆盖。

本地地图页浏览器回归：选中 Roma 后连续缩小三级，标记和预览卡均保持可见并随地图移动。同一区域的聚合数在选中时为 18，点击已选标记取消后变为 19，卡片关闭且相册重新进入聚合。另用浏览器 DOM 身份检查 Paris 标记：修复前点击固定使 `backendNodeId` 从 300 变成 340；改成扁平子节点数组后，点击固定和取消固定时均保持 744，确认标记没有重挂载。

待验证：视口边缘的卡片碰撞位置尚未单独逐项检查。
