# 图片绘制过渡优化

在预览原图时，在加载图片完成后到使用 webgl 绘制过程中，Afilmory 右下角有个解码中的提示，而我们的没有，会有些突兀，需要补上

## 已实施

已完成，主改动在：

- [components/gallery/progressive-view.tsx](/Users/xin/Developer/lumine/components/gallery/progressive-view.tsx)
- [components/webgl-viewer/webgl-image-viewer-engine.ts](/Users/xin/Developer/lumine/components/webgl-viewer/webgl-image-viewer-engine.ts)

## 问题根因

此前预览链路只有“网络加载中”状态。

也就是说：

1. 从原图 URL `fetch` 到 `blob`
2. 网络读取阶段会显示右下角 loading
3. 一旦 `blob` 就绪，组件立刻切到 `webgl` 模式
4. 但 `WebGLImageViewer` 内部其实还要继续做 `Image` 加载、纹理解码、`createImageBitmap()` 和首帧绘制

这段时间之前没有任何提示，所以视觉上会感觉从加载完成到正式绘制之间有一个“空档”。

## 具体改动

### 1. 接入 WebGL loading 回调

`WebGLImageViewer` 本身就支持 `onLoadingStateChange`，只是之前没有在当前项目里真正接到 UI 上。

现在 [progressive-view.tsx](/Users/xin/Developer/lumine/components/gallery/progressive-view.tsx) 已经：

1. 在 `webgl` 模式下监听 `onLoadingStateChange`
2. 单独维护 WebGL 阶段的 loading 状态
3. 在右下角继续显示一块状态提示

这样网络读取结束后，到 WebGL 首次绘制完成前，用户仍然能看到明确的阶段提示。

### 2. 补上 “Decoding / Preparing texture” 状态

右下角状态现在分成两类：

1. 网络阶段：继续显示 `Loaded xx%` 和字节进度
2. WebGL 阶段：显示 `Decoding image` 或 `Preparing texture`

并在第二行统一提示 `Preparing first render`，让“下载完成但还没真正显示”的这段时间有明确反馈。

### 3. 统一 WebGL 内部 loading message

[webgl-image-viewer-engine.ts](/Users/xin/Developer/lumine/components/webgl-viewer/webgl-image-viewer-engine.ts) 里原本的阶段消息是中文。

现在已经改成英文：

1. `Loading image`
2. `Preparing texture`

这样当前项目的预览 UI 文案保持一致，不会在英文界面里混入中文内部状态。

## 当前结果

现在预览原图时，右下角状态会覆盖两个阶段：

1. 原图网络读取
2. WebGL 首帧准备

所以从缩略图到底层 WebGL 画面之间的过渡不再是“无提示的空档”，会更接近 Afilmory 的观感。
