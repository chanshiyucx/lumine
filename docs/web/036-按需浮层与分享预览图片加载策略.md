# 按需浮层与分享预览图片加载策略

- 状态：已实施，待人工视觉回归
- 日期：2026-09-25
- 范围：地图浮层封面、Viewer 分享弹窗预览图

## 背景

`ThumbnailImage` 默认使用 `loading="lazy"`，首页及相册详情的瀑布流按前 `3 × 列数` 张照片选择 `eager`。相册列表单独为前四个封面选择 `eager`。这些列表在页面渲染时就存在，需要避免一次请求所有图片。

地图标记也有自己的加载策略：视野内的标记使用 `eager`，其余使用 `lazy`。预览缩略图栏保持 `lazy`，用户悬停后的放大预览使用 `eager`；Viewer 当前照片的缩略图和共享转场使用 `eager`。这些策略由各自的展示时机决定，不需要改动 `ThumbnailImage` 的默认值或移除它的 `loading` 参数。

## 调整

1. [AlbumCoverLink](../../web/components/map/album-cover-link.tsx)只在地图相册浮层和聚合浮层中使用。浮层打开后才挂载，且每个浮层最多显示少量封面，因此组件内部统一使用 `loading="eager"`，删除自身的 `loading` 参数及相册浮层中的传参。聚合浮层封面此前使用默认 `lazy`，现在与相册浮层一致。
2. [ViewerShareDialog](../../web/components/viewer/viewer-share-dialog.tsx)只在用户打开分享弹窗时挂载。分享预览图设置 `loading="eager"`，打开时立即请求该图；已有的加载提示和错误处理保持原样。

这里的 `eager` 表示图片元素挂载后立即开始加载；它不会在浮层或弹窗打开之前预取。未为这些图片设置 `preload` 或更高的网络优先级。

## 验证与后续观察

本次运行 `pnpm type-check`、`pnpm lint`、Prettier 检查和 `git diff --check`。人工回归重点是地图聚合浮层首次打开时的封面加载、相册浮层首次打开、分享弹窗首次打开时预览图及加载失败提示。

地图标记的首次渲染使用 `WORLD_BOUNDS` 作为视野范围，因此当时渲染的标记都会被判为 `eager`。这属于标记加载策略，和按需浮层不同；如要优化地图初始请求，应先用浏览器网络记录确认请求数量与时序，再调整标记策略。
