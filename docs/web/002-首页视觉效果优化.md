# 首页视觉效果优化

## 背景

在第一版瀑布流首页完成后，首页视觉和 DOM 结构还存在两个问题：

1. 与 Afilmory 参考实现相比，卡片感仍然偏重，圆角、间距和层级都偏多
2. 后续继续压平视觉后，又暴露出 hover 抖动、横向滚动和 header 高度不合适的问题

这个文档记录首页视觉优化的两轮调整：

- `v1`：收敛 DOM 结构和基础视觉
- `v2`：修正 hover、布局宽度和 sticky header 的细节问题

## 优化 v1

### 目标

需要改善首页效果呈现：

1. 图片不需要任何圆角；图片之间的 gap 只有 `2px`
2. 略缩图 `webp` 不需要使用 `canvas` 展示，直接使用 `img` 标签即可
3. 首页 DOM 应该尽量简化，不需要这么多 `button` 包裹和 `canvas` 元素

Afilmory 的图片 Item DOM 如下，目标是向这个层级靠拢：

```html
<div role="gridcell">
  <div class="group relative w-full cursor-pointer overflow-hidden" data-photo-id="DSCF5955">
    <img class="absolute inset-0 h-full w-full" src="data:image/png;base64,iVBO">
    <img
      alt="DSCF5955"
      loading="lazy"
      class="absolute inset-0 h-full w-full object-cover duration-300 group-hover:scale-105"
      src="https://r2.innei.ren/.afilmory/thumbnails/DSCF5955.jpg"
    >
    <div class="pointer-events-none">
      <div class="pointer-events-none absolute inset-0 bg-linear-to-t from-black/80 via-black/20 to-transparent opacity-0 transition-opacity duration-300 group-hover:opacity-100"></div>
      <div class="absolute inset-x-0 bottom-0 p-4 pb-0 text-white">
        <div class="mb-3">
          <h3 class="mb-2 truncate text-sm font-medium opacity-0 group-hover:opacity-100">DSCF5955</h3>
          <div class="mb-2 flex flex-wrap gap-2 text-xs text-white/80 opacity-0 group-hover:opacity-100">
            <span>HIF</span><span>•</span><span>7728 × 5152</span><span>•</span><span>14.2MB</span>
          </div>
          <div class="flex flex-wrap gap-1.5">
            <span class="rounded-full bg-white/20 px-2 py-0.5 text-xs text-white/90 opacity-0 backdrop-blur-sm group-hover:opacity-100">人文</span>
          </div>
        </div>
      </div>
    </div>
  </div>
</div>
```

### v1 已实施内容

本轮实际修改集中在：

- `components/photo-gallery.tsx`
- `lib/photos.ts`
- `lib/blurhash.ts`

#### 1. 首页 DOM 收敛

首页图片项从“外层 `button` + 多层视觉包装”收敛为：

- `div[role="gridcell"]`
- 内层 `div[role="button"]`
- 底层 blur 预览图
- 顶层缩略图
- 单个 overlay 信息层

这样保留可访问性和键盘打开能力，同时把首页卡片结构压到接近参考实现的复杂度。

#### 2. 去掉首页圆角与大间距

首页卡片已经改为纯平铺图块：

- 无圆角
- 无大卡片边框
- 图块之间统一 `2px` 间距

瀑布流的列间距和行间距都统一使用 `gap = 2`。

#### 3. 首页不再用 canvas 展示缩略图

首页主图一直都是 `thumbnail.webp`，这一点保持不变；同时 blur 占位也不再通过首页 DOM 里的 `canvas` 实现，而是改为：

- 在 `lib/blurhash.ts` 里把 blurhash 解码为极小尺寸像素图
- 再生成 SVG data URL
- 在 `lib/photos.ts` 中预先挂到 `blurDataUrl`
- 首页直接渲染为底层 `img`

这样首页最终是“双 img”结构，而不是 `canvas + img`。

#### 4. 首页信息层样式调整

hover 信息层改成更贴近 Afilmory 的方式：

- 底部黑色渐变遮罩
- 标题
- `格式 / 分辨率 / 文件大小`
- 一个轻量标签 chip

#### 5. 修复刷新后首列缩略图透明不显示的问题

在 v1 调整过程中发现一个边界问题：

- 首屏图片可能在 React 绑定 `onLoad` 之前就已经命中缓存加载完成
- 结果 `thumbnail` 的透明度状态一直停留在 `0`
- 表现为刷新后只看到 blurhash，看不到真实缩略图

为此在首页缩略图上增加了 `img.complete` 检查：

- 组件挂载后如果图片已经完成加载，则主动把 `isLoaded` 切为 `true`
- 如果是异常完成且 `naturalWidth === 0`，则切到错误态

### v1 效果总结

v1 之后，首页已经完成以下目标：

- 首页更接近 Afilmory 的平铺式瀑布流
- DOM 明显比初版更轻
- blur 过渡从 `canvas + img` 调整为更稳定的双 `img`
- gap 压缩到 `2px`

但 v1 还遗留了 hover 和布局上的细节问题，因此进入 v2。

## 优化 v2

### 待解决问题

1. 图片 hover 放大时，边缘有抖动；视觉上会让中间的 gap 看起来小于 `2px`
2. 禁止容器横向滚动，容器宽度应该是 `100vw`
3. 顶部 header 高度调小，高度 `48px`，即 `h-12`，同时滚动时 sticky 附着

### 问题分析

#### 1. hover 抖动

v1 中缩略图的 `opacity` 过渡和 `scale` 过渡绑定在同一个 `img` 元素上，而且图片直接贴在容器边缘做放大。即使容器本身有 `overflow-hidden`，在浏览器的合成层和亚像素采样下，边缘仍然容易出现：

- 抖动感
- 间距视觉被侵占
- hover 时图块边界不够稳定

#### 2. 横向滚动

首页主容器虽然已经压成全宽视觉，但还没有明确把根容器和主网格都锁到 `100vw / max-w-screen`，在某些情况下仍可能因为：

- sticky header 的内部宽度策略
- hover 图层的合成溢出
- 视口与内容宽度计算差异

产生横向滚动条。

#### 3. header 高度过高

原先 header 是双行结构，内边距也偏大，更像展示型 hero header，而不是“浏览照片时附着在顶部的轻导航条”。

### v2 已实施修复

本轮继续修改：

- `components/photo-gallery.tsx`

#### 1. hover 缩放改成独立图片层

当前结构改为：

- 外层点击容器负责裁切
- 内层单独的 `absolute inset-0 overflow-hidden`
- 真正做缩放的是这个内层里的缩略图 `img`

并且缩放参数改为：

- `transform-gpu`
- `will-change-transform`
- `[backface-visibility:hidden]`
- `duration-500 ease-[cubic-bezier(0.22,1,0.36,1)]`
- 初版先收敛到较小比例，后续对照 Afilmory 调整为 `group-hover:scale-105`

目的不是让 hover 更夸张，而是让它更稳。当前已经按 Afilmory 参考实现的缩放比例 `1.05` 对齐，同时保留独立裁切层，避免放大时直接侵蚀图块之间的 `2px` gap。

#### 2. 根容器切到 `100vw`

v2 首轮尝试曾把首页外层和主内容区显式切到：

- `w-screen`
- `max-w-screen`
- `overflow-x-hidden`

这能强化“满屏”语义，但 `100vw` 本身会把滚动条宽度计算进去，因此在后续调试里发现它反而容易成为横向滚动的根源。最终代码已经回退为：

- `w-full`
- `max-w-full`
- `overflow-x-clip`

同时继续在 `html` / `body` 上禁掉横向溢出。也就是说，v2 的最终稳定解法不是持续坚持 `100vw`，而是回到 `w-full` 并用裁切控制溢出。

#### 3. header 压缩为 `h-12`

顶部 header 已经收敛成：

- 固定高度 `48px`
- `sticky top-0`
- 单行信息布局
- 更小的站点标识、标题和统计信息

现在 header 更像一个浏览状态条，而不是页面内容的一部分，滚动时附着感更明显。

## 当前首页结构

首页现在的主要结构是：

1. `app/page.tsx`
   服务端入口，向客户端组件传入照片集合
2. `components/photo-gallery.tsx`
   首页瀑布流、header、hover 信息层、双 `img` 过渡
3. `lib/photos.ts`
   manifest 解析、图床 URL 拼接、blur 占位数据注入
4. `lib/blurhash.ts`
   blurhash 解码与 SVG data URL 生成

## 当前首页卡片的实际策略

每张卡片由三层视觉构成：

1. 底层 blurhash `img`
   始终存在，保证任何时刻都有视觉占位
2. 顶层 `thumbnail` `img`
   加载完成后淡入，hover 时轻微放大
3. overlay 信息层
   只在 hover 时显示标题、元信息和标签

这套结构比单图透明切换更稳定，也比 `canvas` DOM 更轻。

## 后续可继续优化的点

如果还要继续往 Afilmory 靠近，可以继续做：

1. 使用绝对定位瀑布流，进一步接近参考 DOM 结构
2. 给 hover 信息层增加更细的淡入时序，而不是统一同时出现
3. 根据照片内容或目录信息生成更准确的标签，而不是当前的 album chip
4. 在移动端关闭 hover scale，仅保留信息覆盖层或点击态

## 优化v3

待解决的问题：

1. 首页图片太多列了，参考 Afilmory 的列数计算方法，合理根据屏幕宽度计算列数
2. hover 放大动画太快了，请参考 Afilmory 的动画设计
3. 图片间的 gap 也参考 Afilmory，现在2px有些小了

### v3 已实施修复

本轮继续修改：

- `components/photo-gallery.tsx`

#### 1. 列宽和列数回归 Afilmory 的自动策略

当前列宽配置已经调整为更接近 Afilmory 的自动布局基准：

- mobile 目标列宽：`150px`
- desktop 目标列宽：`250px`
- 最大列数：`8`
- 列间距 / 行间距：`4px`
- 约束列宽：mobile `120~250px`，desktop `200~500px`

在实现上不是简单写死“某个断点几列”，而是：

1. 根据当前容器宽度和目标列宽估算列数
2. 限制最大列数不超过 `8`
3. 再反推每列真实宽度
4. 用最短列优先算法继续分配图片

这会比之前的配置明显减少大屏上的列数，视觉密度也更接近 Afilmory。

#### 2. hover 动画节奏对齐 Afilmory

本轮将 hover 主图动画收回到更接近参考实现的节奏：

- `transition-[opacity,transform]`
- `duration-300`
- `ease-out`
- `group-hover:scale-105`

也就是：

- 比上一版更短
- 缓动更直接
- 放大比例与 Afilmory 的 `scale-105` 一致

上一版的 `500ms + 自定义 cubic-bezier` 虽然更柔，但整体气质已经偏离参考实现，v3 重新拉回去了。

#### 3. gap 从 `2px` 调整为 `4px`

首页瀑布流的列间距和行间距都已经从 `2px` 调整为 `4px`，并且主内容区 padding 也同步拉回到更接近参考实现的值：

- mobile：`4px`
- desktop：`16px`

这样首页不会像前一版那样过于拥挤，图块之间的呼吸感也更接近 Afilmory。

### v3 效果总结

v3 调整后，首页相对于 v2 的主要变化是：

- 列数减少，单张图片的存在感更强
- hover 节奏更接近参考实现
- gap 和边缘留白更自然
- 视觉密度从“压满”回到“可浏览”
