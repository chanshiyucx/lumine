# 站内路由路径管理优化

## 文档状态

- 状态：已实施
- 日期：2026-09-22
- 范围：照片与相册站内路由的生成、识别和解析

## 优化原因

照片路径、相册路径、Open Graph 路径和 Viewer pathname 解析原本分散在多个模块中。Viewer 还自行维护了 `/photos/` 前缀、匹配正则和解码逻辑。

本次将站内路由规则集中到一个模块，确保路径格式、编码和解析只有一个事实来源。

## 新增路由路径模块

新增 `web/lib/route-paths.ts`：

| 函数 | 职责 |
| --- | --- |
| `getAlbumPath(albumKey)` | 生成相册页路径 |
| `getPhotoPath(slug)` | 生成照片页路径 |
| `getPhotoOgPath(slug)` | 生成照片 Open Graph 图片路径 |
| `getPhotoSlugFromPathname(pathname)` | 识别照片 pathname，解码并返回 slug |
| `isPhotoPathname(pathname)` | 判断 pathname 是否位于照片路由下 |

模块内统一使用 `encodePathSegment()` 和 `decodeRawPathSegment()`，调用方不再自行处理路径编解码。

## 调整内容

### 路由生成

- `getPhotoPath()` 从 `web/lib/photo/index.ts` 移入 `route-paths.ts`。
- `getPhotoOgPath()` 从 `web/lib/photo/share.ts` 移入 `route-paths.ts`。
- `getAlbumPath()` 从 `web/lib/albums.ts` 移入 `route-paths.ts`。
- 分享、相册卡片和地图数据统一从 `route-paths.ts` 导入路径函数。

### Viewer 路径解析

`use-viewer-controller.ts` 改为使用：

- `getPhotoPath()` 生成 Viewer URL。
- `getPhotoSlugFromPathname()` 解析当前照片 slug。
- `isPhotoPathname()` 判断当前是否为照片路由。

Viewer 不再包含 `/photos/` 字面量、路径正则或 `decodeRawPathSegment()` 调用。

## 职责划分

| 模块 | 职责 |
| --- | --- |
| `route-paths.ts` | 站内路由生成与解析 |
| `url-segments.ts` | 通用路径段编码、解码与 NFC 归一化 |
| `media-url.ts` | 外部媒体源、manifest 和 map URL |
| `photo/share.ts` | 生成包含运行时 origin 的绝对分享 URL |
| 路由 `_data.ts` | 加载具体照片或相册并处理 404 |
