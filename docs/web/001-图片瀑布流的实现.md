# 图片瀑布流的实现

## 目标

当前项目是展示我用相机拍摄照片的网站，首页是沉浸式瀑布流风格，优先完成两个核心场景：

1. 首页瀑布流，根据屏幕宽度智能分列展示图片
2. 点击图片进入全屏预览，支持左右切换和底部缩略图跳转
3. 首页只加载 `thumbnail`，并用 `blurhash` 做占位
4. 预览层只在打开时加载 `original`

## 已实施方案

### 1. 数据层

新增 `lib/photos.ts`，负责把根目录 `manifest.json` 解析成前端直接可用的数据结构：

- 用 `zod` 校验 manifest 结构，避免字段缺失时静默失败
- 统一把 `original.url`、`thumbnail.url` 拼接成完整 R2 地址
- 生成页面直接消费的 `GalleryPhoto` 类型
- 从目录名 `20241229-Roma` 推导出专辑标题 `Roma · 2024.12.29`

同时把图床域名抽到 `lib/site-config.ts` 的 `mediaOrigin`，避免散落在组件里硬编码。

### 2. 首页瀑布流

首页现在改成：

- 服务端入口：`app/page.tsx`
- 客户端画廊：`components/photo-gallery.tsx`

具体实现：

- 页面本身仍然是 App Router 的 Server Component，只负责把 `photoCollection` 传给客户端组件
- `PhotoGallery` 用 `ResizeObserver` 监听容器宽度
- 根据容器宽度选择目标列宽、最大列数和列间距
- 使用“最短列优先”算法把图片逐张分配到当前高度最短的列里，得到真实瀑布流而不是简单 CSS 多列流
- 卡片只加载 `thumbnail`
- 图片加载前先显示 `blurhash` 画布，占位期间不会出现空白块
- 图片卡片保留了 hover 渐变、编号和基础尺寸信息，整体氛围贴近参考图，但保留了当前项目自己的排版

列数策略当前是：

- `< 480px`：最多 2 列
- `< 768px`：最多 3 列
- `< 1280px`：最多 5 列
- `>= 1280px`：最多 6 列

这套规则不是死写列数，而是结合“目标列宽 + 最大列数”动态计算，宽屏下会更自然。

### 3. Blurhash 占位

新增 `components/blurhash-canvas.tsx`，在客户端直接解码 blurhash 到 canvas。

这样做的原因：

- 不额外引入第三方依赖
- 首页和预览层都能复用
- 可以直接作为底层模糊背景使用

表现方式：

- 首页卡片：blurhash 先显示，缩略图加载完成后淡出
- 预览层：blurhash 既作为主图加载前的占位，也作为全屏背景模糊氛围层

### 4. 全屏预览

新增 `components/photo-lightbox.tsx`，实现预览层。

能力包括：

- 点击任意卡片打开全屏预览
- `Escape` 关闭
- 左右按钮切换
- 键盘左右键切换
- 底部缩略图条跳转当前照片
- 当前缩略图自动滚动到可视区域
- 打开预览后锁定页面滚动

加载策略：

- 预览层优先尝试加载 `original`
- 如果 `original` 加载失败，再回退到 `thumbnail`
- 会预加载前后一张图片，减少切换时的等待

这部分是当前实现里最重要的兜底设计，因为 manifest 里的原图是 `.HIF / image/heif`，浏览器兼容性并不稳定。

### 5. 视觉层和全局样式

更新了：

- `app/layout.tsx`
- `app/globals.css`

调整内容：

- 字体改为 `Manrope + Cormorant Garamond + Geist Mono`
- 页面基调改成深色沉浸式背景
- 顶部加入轻量毛玻璃导航条
- 增加了瀑布流入场动画和预览层淡入动画
- 定义了统一的颜色变量、字体变量和全局选择态

### 6. 工程层调整

根目录的 Next.js 应用原本会把 `docs/web` 这个参考项目也一起纳入 TypeScript 和 ESLint 检查，导致：

- `pnpm type-check` 失败
- `pnpm build` 在 TypeScript 阶段失败
- `pnpm lint` 被参考工程里的历史问题阻塞

因此补充了两个隔离配置：

- `tsconfig.json` 排除 `docs/web`
- `eslint.config.mjs` 忽略 `docs/web/**`

这个调整是合理的，因为 `docs/web` 在当前仓库里只是参考实现，不属于根目录 Next 应用的构建产物。

## 已知限制

### 1. 原图格式是 HEIF / HIF

当前 manifest 的 `original` 是 `.HIF` 文件，很多浏览器并不能稳定直接显示。因此现在的策略是：

- 先尝试原图
- 原图失败则自动降级到缩略图

这保证了页面可用，但也意味着：

- 某些浏览器里预览层不一定能看到真正原图
- 如果后续希望跨浏览器稳定显示高清预览，建议在生成 manifest 时同步产出可浏览器直接显示的原图格式，例如 `webp` / `jpeg` / `avif`

### 2. 预览层目前不带 URL 状态

现在的预览器是前端 overlay，不会把当前照片写入路由或 query 参数。因此：

- 刷新页面会回到首页关闭态
- 不能直接分享“打开到第 N 张图”的链接

如果后面需要分享态，可以把当前索引同步到 `?photo=` 或 hash。

### 3. 暂未实现触摸手势切换

当前移动端可用，但主要交互仍然是：

- 点击缩略图
- 点击左右按钮

如果后面更重视手机体验，可以继续加：

- 左右滑动切换
- 双指缩放
- 下滑关闭
