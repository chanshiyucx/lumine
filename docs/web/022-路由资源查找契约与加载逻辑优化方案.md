# 路由资源查找契约与加载逻辑优化方案

## 文档状态

- 状态：已实施
- 日期：2026-09-22
- 范围：照片和相册动态路由的资源加载、参数归一化与 404 判定

## 优化目标

1. 让页面、Metadata 和 Open Graph 图片共享同一套资源加载逻辑。
2. 修正 Next.js 已解码 `params` 被二次 URI 解码的问题。
3. 照片和相册 lookup 都在查找前执行 Unicode NFC 归一化。
4. 保留现有并行加载、缓存、Metadata、Open Graph 和 404 行为。

## 参数契约

| 输入 | 处理方式 | 原因 |
| --- | --- | --- |
| Next.js `params.photoId` | `normalizePathSegment()` | `params` 已 URI 解码，只需统一 Unicode 形式 |
| Next.js `params.albumKey` | `normalizePathSegment()` | 避免二次 URI 解码 |
| pathname 中手动截取的路径段 | `decodeRawPathSegment()` | 该值仍是原始 URL 文本 |
| 写入 URL 的 slug/key | `encodePathSegment()` | 确保路径段正确编码 |

## 具体改动

### 1. 提取照片路由加载逻辑

新增 `web/app/photos/[photoId]/_data.ts`，导出：

```ts
loadPhotoRouteData(
  params: PageProps<'/photos/[photoId]'>['params'],
)
```

该函数通过 `Promise.all()` 并行等待 `params` 和 `getPhotoCollection()`，统一处理 `photoId` NFC 归一化、slug lookup 和 `notFound()`，返回当前照片与完整照片列表。

`page.tsx` 和 `opengraph-image.tsx` 均使用该函数，保证页面、Metadata 和 Open Graph 的资源查找与 404 规则一致。

### 2. 提取相册路由加载逻辑

新增 `web/app/albums/[albumKey]/_data.ts`，导出：

```ts
loadAlbumRouteData(
  params: PageProps<'/albums/[albumKey]'>['params'],
)
```

该函数通过 `Promise.all()` 并行等待 `params` 和 `getAlbumCatalog()`，统一处理相册 lookup 和 `notFound()`。

`page.tsx` 和 `opengraph-image.tsx` 均使用该函数，保证页面、Metadata 和 Open Graph 的资源查找与 404 规则一致。

### 3. 修正相册 lookup

修改 `web/lib/album-catalog.ts`：

```ts
albumsByKey.get(normalizePathSegment(albumKey))
```

`albumKey` 来自 Next.js `params`，已经完成 URI 解码。lookup 前只做 NFC 归一化，避免将字面量 `%2F` 等内容再次解码。

### 4. 明确原始 URL 解码函数

将 `web/lib/url-segments.ts` 中的 `decodePathSegment()` 重命名为 `decodeRawPathSegment()`，函数实现不变。

`web/components/viewer/hooks/use-viewer-controller.ts` 同步使用新名称。新名称明确该函数只处理从 pathname 手动截取的原始 URL 片段。
