# 路由资源查找契约与加载逻辑优化方案

## 文档状态

- 状态：已实施
- 日期：2026-09-22
- 范围：照片和相册动态路由的资源加载、参数归一化与 404 判定

2026-09-28 补充：相簿详情页曾全部返回 404，原因是开发服务器保留了已删除的动态路由。随后确认当前 Next.js 版本的页面组件与 Metadata、Open Graph 图片收到的路由参数编码形式不同；当前查找契约见 [可读名称路由方案](./047-可读名称路由方案.md)。

## 优化目标

1. 让页面、Metadata 和 Open Graph 图片共享同一套资源加载逻辑。
2. 修正 Next.js 已解码 `params` 被二次 URI 解码的问题。
3. 照片和相册 lookup 都在查找前执行 Unicode NFC 归一化。
4. 保留现有并行加载、缓存、Metadata、Open Graph 和 404 行为。

## 参数契约

| 输入 | 处理方式 | 原因 |
| --- | --- | --- |
| 页面组件的 `params` | `decodeEncodedPathSegment()` | 当前 Next.js 版本在这里传入仍带 URI 编码的动态段 |
| Metadata、Open Graph 图片的 `params` | 直接传入加载器 | 这些入口收到已解码的动态段 |
| pathname 中手动截取的路径段 | `decodeEncodedPathSegment()` | 该值仍带 URI 编码 |
| 写入 URL 的 slug/key | `encodePathSegment()` | 确保路径段正确编码 |

## 具体改动

### 1. 提取照片路由加载逻辑

新增 `web/app/photos/[photoId]/_data.ts`，导出：

```ts
loadPhotoRouteData(photoId: string)
```

各入口先将路由参数转为已解码的照片 slug。加载器读取 `getPhotoCollection()`，统一处理 NFC 归一化、slug lookup 和 `notFound()`，返回当前照片与完整照片列表。

`page.tsx` 和 `opengraph-image.tsx` 均使用该函数，保证页面、Metadata 和 Open Graph 的资源查找与 404 规则一致。

### 2. 提取相册路由加载逻辑

新增 `web/app/albums/[albumId]/_data.ts`，导出：

```ts
loadAlbumRouteData(albumId: string)
```

各入口先将路由参数转为已解码的相簿名。加载器读取 `getAlbumCatalog()`，统一处理相册 lookup 和 `notFound()`。

`page.tsx` 和 `opengraph-image.tsx` 均使用该函数，保证页面、Metadata 和 Open Graph 的资源查找与 404 规则一致。

### 3. 修正相册 lookup

修改 `web/lib/album/catalog.ts`：

```ts
albumsByKey.get(normalizeAlbumKey(albumKey))
```

传入 lookup 的相簿名已在入口处理。lookup 前只做 NFC 归一化，不在资源查找层做 URI 解码。

### 4. 明确原始 URL 解码函数

将 `web/lib/url-segments.ts` 中的 `decodePathSegment()` 改名为 `decodeEncodedPathSegment()`，明确该函数只处理仍带 URI 编码的路径段。

Viewer 通过 `route-paths.ts` 使用该函数解析 pathname；页面组件也用它处理当前 Next.js 版本传入的编码后动态段。
