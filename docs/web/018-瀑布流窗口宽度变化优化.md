# 瀑布流窗口宽度变化优化

拖动窗口改变屏幕宽度，列数重排和图片宽度变化很不流畅，需要优化，参考 Afilmory，能够实时重排

## 问题判断

根因不只是列宽策略，而是我们之前仍然依赖 `masonic` 的高层 `<Masonry>` 组件。

当前实现和 Afilmory 的关键差异是：

1. 我们用的是库提供的高层 `<Masonry>`
2. Afilmory 用的是自己封装的一层 `Masonic` wrapper
3. 它直接控制 `usePositioner`、`useMasonry`、`createResizeObserver` 和容器宽度监听

这意味着在窗口拖拽时，Afilmory 的瀑布流重排链路是可控的，而我们之前是把 resize 行为交给库内部黑盒。实际表现就是：

1. 列数切换不够跟手
2. 列宽变化不是连续响应，而是有明显滞后
3. 视觉上就会觉得重排“顿一下再跳”

## 已实施改动

### 1. 引入本地 `Masonic` wrapper

新增文件：

- [components/gallery/masonic.tsx](/Users/xin/Developer/lumine/components/gallery/masonic.tsx)
- [components/gallery/hooks/use-viewport-size.ts](/Users/xin/Developer/lumine/components/gallery/hooks/use-viewport-size.ts)

现在首页瀑布流不再直接用 `masonic` 的高层 `<Masonry>`，而是切到本地 wrapper。这个 wrapper 参考了 Afilmory 的实现方式，自己控制：

1. `useViewportSize`
2. `useContainerPosition`
3. `usePositioner`
4. `createResizeObserver`
5. `useMasonry`

这样 resize 时的列宽和重排，不再完全受库内部默认实现影响。

### 2. 列宽策略回到 Afilmory 风格

文件：

- [components/gallery/masonry-grid.tsx](/Users/xin/Developer/lumine/components/gallery/masonry-grid.tsx)
- [components/gallery/lib/masonry-layout.ts](/Users/xin/Developer/lumine/components/gallery/lib/masonry-layout.ts)

调整后：

1. `masonry-grid.tsx` 改用本地 `Masonic`
2. `getMasonryConfig()` 只保留 Afilmory 风格的输入参数：
3. 移动端 `150px`
4. 桌面端 `250px`
5. 桌面端最多 `8` 列

真实列宽交给 `usePositioner()` 根据容器实时宽度计算，不再在外层提前算“修正后列宽”。

### 3. 保留 viewport resize 的实时更新

`use-viewport-size.ts` 继续保留，但现在它的职责只剩：

1. 让 breakpoint 判断跟随真实 viewport
2. 触发本地 `Masonic` wrapper 重新计算容器和列布局

## 当前结果

现在拖动窗口时：

1. 列数切换会更接近 Afilmory 的节奏
2. 图片宽度变化由本地 positioner 直接控制
3. 重排链路已经从库黑盒切回项目内可控代码
