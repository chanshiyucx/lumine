# 照片按拍摄时间排序

## 文档状态

- 状态：已实施
- 日期：2026-09-22
- 范围：服务端照片集合的排序规则

## 背景

Pipeline 按图片路径组织 manifest，前端原先将照片数组倒序展示。路径包含相册文件夹日期，因此持续更新的旧相册中，新拍摄的照片仍会出现在首页后面。

此前对线上 manifest 的检查覆盖 22 个相册、458 张照片（数据更新时间为 2026-09-20）。只有 Munich 的拍摄时间范围与其他相册交叉；Changsha 的实际拍摄日期晚于文件夹日期；Munich 和 Napoli 的内部文件名顺序也存在与拍摄时间不一致的情况。

目标是所有照片按 `takenAt` 倒序展示，最新拍摄的照片优先，而非按加入网站的时间排序。

## 方案与实现

在 `web/lib/photo/collection.ts` 的 `getPhotoCollection()` 中，读取并校验 manifest 后统一排序：

```ts
const photos = manifest.photos.toSorted(
  (left, right) => Date.parse(right.takenAt) - Date.parse(left.takenAt),
)
```

- 使用时间戳比较，正确处理 `takenAt` 中不同的时区偏移，不直接比较字符串。
- 只按拍摄时间排序，不添加第二排序条件。
- 使用 `toSorted()` 返回新数组，不修改原始 manifest 数组。
- 排序在标记为 `server-only` 的数据层执行，保留现有 React `cache()` 请求内复用和 manifest 的 30 秒再验证配置，浏览器无需额外排序。
- 沿用现有 `takenAt` 字段及校验，不新增时间字段或修改 manifest 格式。

Pipeline 负责产出照片及元数据，网站服务端数据层负责展示顺序。无需重新运行 Pipeline，也无需调整 manifest 中的物理排列顺序。

## 展示影响

- 首页瀑布流、首页查看器和照片独立页面使用统一的拍摄时间倒序。
- 相册内部照片继承同一顺序；相册列表仍按相册文件夹日期倒序排列。
- 相册封面及依赖前几张照片的地图预览、分享图片随新顺序选图，优先使用最近拍摄的照片。
- 首页滚动时的日期和地点仍由当前可见照片决定；跨相册时间交叉时，相册名称可能随照片切换。
