# 图片预览组件优化

## 背景

上一阶段首页瀑布流已经基本稳定，下一阶段目标是把预览层从“基础 lightbox”升级为更接近 Afilmory 的查看器：

1. 全屏预览布局，而不是简单居中的弹层
2. 主图区优先展示尽可能大的原图，且完整可见
3. 主图需要有真实的加载进度
4. 底部缩略条改为无缝、按原比例横向排布
5. 打开预览时 URL 可直达，刷新后仍能打开同一张图

## 结论

本轮已经完成预览层的下一阶段优化，核心策略如下：

1. 预览层改为全屏三段式结构：左侧主图区、右侧信息区、底部横向缩略条
2. 主图渲染链路改为“同源流式加载 + 进度显示 + WebGL 渲染 + 失败回退”
3. 预览打开时使用 `history.pushState/replaceState` 同步到 `/photos/[photoId]`，但不触发实际页面跳转
4. 刷新直达依赖真实的 Next 路由 `/photos/[photoId]`，服务端仍然渲染同一套瀑布流页面，并在客户端 hydration 后自动展开对应预览

## 已实施内容

### 1. 全屏布局重构

当前预览组件 [components/photo/photo-viewer.tsx](/Users/xin/Developer/lumine/components/photo/photo-viewer.tsx) 已改成全屏查看器：

1. 左侧为主图区，主图始终按 `contain` 逻辑在可用区域内放到最大并完整展示
2. 右侧为信息面板，占位结构已经保留，当前只展示基础标题和尺寸信息，详细元数据后续再补
3. 底部为独立缩略条，不再是简单的小方块列表

### 2. 原图加载进度与 WebGL 渲染

当前实现不再只是用 `Image()` 预加载后直接切图，而是新增了两层能力：

1. [components/photo/photo-progressive-view.tsx](/Users/xin/Developer/lumine/components/photo/photo-progressive-view.tsx)
2. `@afilmory/webgl-viewer`

具体链路：

1. 先显示 blurhash 背景和缩略图底图
2. 再从同源接口 `/api/photos/[photoId]` 流式拉取原图字节
3. 在拉取过程中显示百分比、已加载字节和进度条
4. 原图解码成功后优先进入 WebGL canvas 渲染
5. 如果 WebGL 不可用或原图无法正常解码，则回退到普通图片显示
6. 如果原图彻底不可用，则继续回退到缩略图预览

之所以增加同源接口 [app/api/photos/[photoId]/route.ts](/Users/xin/Developer/lumine/app/api/photos/[photoId]/route.ts)，是因为当前 R2 资源响应头没有暴露可直接给浏览器 `fetch + blob` 使用的跨域能力。没有这层代理，就拿不到稳定的字节进度，也无法可靠进入 WebGL 渲染链。

### 3. 缩略条重构

底部缩略条已经按 Afilmory 的方向做了重构：

1. 横向滚动
2. 图片之间无 gap
3. 固定高度，宽度按各自原始比例计算
4. 默认黑白显示
5. 当前项和 hover 项恢复彩色
6. 桌面端 hover 时在上方显示悬浮大图预览

当前这一块仍然是轻 DOM 实现，没有引入额外的虚拟列表依赖。

### 4. URL 同步与刷新直达

这一轮同时补了真正的可分享路径能力：

1. 数据层 [lib/photos.ts](/Users/xin/Developer/lumine/lib/photos.ts) 新增 `slug`
2. 根页面 [app/page.tsx](/Users/xin/Developer/lumine/app/page.tsx) 和详情路径 [app/photos/[photoId]/page.tsx](/Users/xin/Developer/lumine/app/photos/[photoId]/page.tsx) 复用同一个 gallery 页面组件 [components/photo/photo-gallery-page.tsx](/Users/xin/Developer/lumine/components/photo/photo-gallery-page.tsx)
3. 瀑布流组件 [components/photo/photo-masonry.tsx](/Users/xin/Developer/lumine/components/photo/photo-masonry.tsx) 在打开/切换/关闭预览时用 History API 同步 URL
4. 关闭预览后直接回到瀑布流 URL `/`

这套实现满足了两个目标：

1. 用户点击打开预览时，没有真正的页面切换感知
2. 用户刷新 `/photos/DSC02890` 这样的链接后，仍然能落到同一张图的预览态

## 当前取舍

### 1. 右侧信息面板仍是占位态

这部分本轮没有接入完整 EXIF、相机参数、地理位置等信息，只保留了容器和基础头部。这样做是为了先把布局、加载链路和 URL 状态稳定下来。

### 2. WebGL 渲染目前直接复用了 Afilmory 的 viewer

当前主图区在 [components/photo/photo-progressive-view.tsx](/Users/xin/Developer/lumine/components/photo/photo-progressive-view.tsx) 中直接接入 `@afilmory/webgl-viewer`，因此已经具备 Afilmory 同源的 WebGL 查看器能力。这一版仍然保留了我们自己的网络进度、转码和失败回退逻辑，避免把整套预览链路一次性替换过大。

### 3. 原图格式兼容性仍受浏览器能力影响

manifest 中原图实际是 `HIF/HEIF`。即使已经走了同源代理，如果浏览器本身解码不了原图，当前仍然会自动回退到缩略图。这个行为是保底策略，不是异常。
