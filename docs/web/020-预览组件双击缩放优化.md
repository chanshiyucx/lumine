# 预览组件双击缩放优化

## 背景

预览器原本参考 Afilmory，将双击缩放设计为三档循环：

1. `fit`：在视口内完整显示照片
2. `fill`：铺满视口，允许另一个维度溢出
3. `100%`：按照原始像素尺寸显示

这套逻辑的目的是避免手机端从 `fit` 直接跳到 `100%` 时放大幅度过大，因此在中间增加了 `fill`。但它同时把“沉浸观看”和“像素级检查”两个不同任务放进了同一个手势循环，会导致：

1. 双击次数与结果不易预测
2. 高像素照片在手机上进入 `100%` 时跳变过大
3. 照片与视口宽高比接近时，`fill` 变化过小，双击后容易看起来没有反应
4. 自由缩放后再双击会继续向更大档位前进，而不是稳定地回到全图

## 设计决策

鼠标双击与触屏双击改为统一的二态语义：

```text
fit ⇄ smart fill
```

具体行为：

1. 当前位于 `fit` 时，双击进入 `smart fill`
2. 当前位于任何非 `fit` 缩放状态时，双击直接回到 `fit`
3. 缩放仍然以用户双击的位置为锚点
4. 双指捏合和鼠标滚轮继续提供自由缩放，不再把 `100%` 强制放入双击循环

二态切换保证了手势的可逆性：用户无需记住当前位于第几档，只需理解“看全图”与“聚焦查看”两个状态。

## Smart fill 计算规则

`smart fill` 不是固定倍率，而是根据照片、视口和原始像素尺寸动态计算。

### 1. 默认目标为 fill

`fill` 使照片的一个维度恰好填满视口，另一个维度可以溢出。相对于 `fit` 的缩放倍率为：

```text
fillRelativeScale = fillPixelScale / fitPixelScale
```

这是大多数普通照片的聚焦态，能在不直接跳入像素级细节的前提下减少留白。

### 2. 不超过原始像素尺寸

原始像素尺寸相对于 `fit` 的倍率为：

```text
originalRelativeScale = 1 / fitPixelScale
```

实际的 fill 目标会被限制在该倍率以内：

```text
cappedFillScale = min(fillRelativeScale, originalRelativeScale)
```

这样当 fill 需要超过照片原始尺寸时，不会继续放大并制造额外模糊。如果照片在 `fit` 状态已经达到或超过原始尺寸，则不再进一步放大。

### 3. 避免放大变化过小

当限制后的 fill 相对 `fit` 增幅达到 `15%` 时，直接使用 fill。

当增幅不足 `15%` 时，双击到 fill 很难被感知。此时使用 `2× fit` 作为备选聚焦倍率，但仍然不超过原始像素尺寸：

```text
smartFillScale = min(2, originalRelativeScale)
```

该规则主要解决桌面宽视口与横向照片宽高比接近时，fill 仅比 fit 大几个百分点的问题。

## 自由缩放后的行为

用户可能通过捏合或滚轮停留在任意倍率。新逻辑不再尝试猜测“下一个更大档位”，而是把任何偏离 `fit` 超过 `1%` 的倍率都视为已放大状态。

因此：

1. `fit` 状态双击：进入 smart fill
2. fill、100% 或任意自由缩放状态双击：回到 fit

这保证了双击的结果始终可预测。

## 实现说明

缩放决策保持为纯函数，不新增 React 状态：

1. [zoomable-image.ts](/Users/xin/Developer/shiyu/lumine/web/components/viewer/lib/zoomable-image.ts) 计算 smart fill 和二态目标倍率
2. [use-zoomable-image.ts](/Users/xin/Developer/shiyu/lumine/web/components/viewer/hooks/use-zoomable-image.ts) 在鼠标双击或触屏双击时读取当前 layout 与 transform，并执行带锚点的缩放动画
3. [zoomable-image.tsx](/Users/xin/Developer/shiyu/lumine/web/components/viewer/zoomable-image.tsx) 继续统一接入鼠标双击与触摸双击

桌面端与触摸端共享同一套二态语义，不依赖视口宽度猜测输入设备。视口尺寸只参与 smart fill 的几何计算。
