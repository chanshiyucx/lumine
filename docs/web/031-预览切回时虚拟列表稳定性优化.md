# Viewer 切回标签页时的虚拟列表稳定性

- 状态：已实施；手动验证仍闪烁
- 日期：2026-09-24
- 范围：背景瀑布流与 Viewer 底部缩略图栏

## 已知现象

仅显示缩略图时，Viewer 从其他标签页返回仍会短暂闪烁。Portal 和独立背景层的调整没有改善；同时注释 `PhotoMasonry` 与 `ViewerThumbnailRail` 后闪烁消失。注释整个组件也同时移除了图片、ThumbHash、滚动容器与样式，因此这个结果不能单独证明 `@tanstack/react-virtual` 本身有缺陷。

TanStack Virtual 在测得滚动视口尺寸为 0 时会计算出空的可见范围，这是源码中的真实行为；目前没有证据证明当前 Chrome 场景一定出现了这次 0 尺寸回调。该分支值得防护，但不将其写成已确认根因。

## 本轮改动

1. 恢复两个暂时注释的区域，让正常画廊和底部缩略图栏继续工作。
2. Viewer 完全打开时，`PhotoMasonry` 的虚拟器暂时不提供滚动元素。TanStack 会断开滚动和尺寸观察，同时保留此前的测量缓存与已渲染的卡片。共享图片入场和退场期间继续连接，以保留源卡片和转场坐标。背景虚拟器暂停时也不向 Header 发布可见照片变化。
3. 瀑布流布局忽略 0 或负的临时宽度，不用无效宽度覆盖最后一份有效布局。
4. 底部缩略图栏在已取得有效视口宽度后忽略临时 0 宽度，避免把已显示的虚拟项替换为空列表。首次真实测量仍正常传给虚拟器。
5. 缩略图栏设置 `useFlushSync: false`。它的缩略图宽度由照片比例和固定栏高估算；若浏览器在恢复时报告尺寸或滚动变化，更新无需强制同步提交。快速滚动时仍需留意虚拟项是否出现短暂空隙。

## 没有采用的处理

不将背景虚拟器简单设置为 `enabled: false`：该选项会清空虚拟项与测量缓存，可能使共享图片转场需要的画廊卡片卸载。不在 JSX 层无条件复用最后一组 `virtualItems`：照片集合、索引或真实视口尺寸变化时，这组旧项可能不再正确。当前防护在测量入口处理瞬时 0 宽度，正尺寸会继续驱动正常更新。

## 手动观察

在原有多窗口切换场景下保持两个区域可见，观察返回 Viewer 时是否还会闪烁。再检查打开与关闭共享图片转场、底部栏快速横向滚动和切图、窗口实际缩放，以及直接进入照片页后关闭 Viewer 的画廊恢复。若仍闪烁，下一轮应保留相同的 DOM 和图片数量，进一步分别停用虚拟器观察或图片层，避免通过删除整个组件作因果判断。

## 验证结果

用户复测后，Viewer 仍会闪烁；保留 `PhotoMasonry`、只注释 `ViewerThumbnailRail` 时不再闪烁。背景瀑布流在 Viewer 打开期间暂停观察的改动可以保留，但本轮对缩略图栏加入的 0 宽度拦截与 `useFlushSync: false` 没有解决现象，下一轮从代码中移除这两项试验性处理，转而缩减底部栏图片和合成层的工作量。
