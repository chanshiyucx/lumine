# 瀑布流返回时恢复滚动位置与无障碍细节

- 日期：2026-10-20
- 状态：已实施，未提交。没有做移动真机测试和读屏测试
- 范围：`web/components/gallery/hooks/use-masonry-scroll-restoration.ts`（新增）、`web/components/gallery/photo-masonry.tsx`、`web/components/gallery/photo-masonry-item.tsx`
- 证据口径：当前源码，已安装的 `next@16.3.4`、`@tanstack/virtual-core@3.17.10` 源码，以及本机 `next start` 生产构建在内置 Chromium 中的实测。实测之外的结论标为“推断”。

## 1. 返回时恢复瀑布流滚动位置

### 1.1 问题

在首页滚到中段（例如第 78 张），点 Header 进入相册页，再按浏览器返回，首页会回到顶部。桌面端（Radix 滚动容器）和移动端（body 滚动）都能复现。

浏览器自带的滚动恢复只管理文档滚动；我们的页面在 Radix viewport 或 body 里滚动，所有页面共用这个滚动元素，浏览器不会为它记录位置。Next 进入新页面时会把这个元素滚到顶部，返回时也不会恢复。

通过 Header 的 Home 图标回首页属于新导航，回到顶部是正确行为；只有浏览器返回或前进才应该回到原位置。

[Afilmory](<../../tmp/afilmory/apps/web/src/pages/(main)/layout.sync.tsx>) 首页之外只有地图页，离开时瀑布流被卸载，代码中没有滚动恢复；地图页的返回按钮调用 `navigate('/')`，属于新导航。按代码判断它有同样的问题，没有实际运行验证。

### 1.2 方案选择

| 做法                                                                                                     | 结论                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 交给浏览器：页面用文档滚动，返回时框架同步渲染旧页面                                                     | 需要把全站改成文档滚动，并且恢复时内容高度已就绪。前者在 [037 号文档](037-首页桌面切移动端卡顿的定位与修复.md)中已被否决，后者在瀑布流上不成立 |
| 路由层手动恢复（React Router `ScrollRestoration`、TanStack Router `useElementScrollRestoration` 的做法） | 采用。离开时保存位置，只在返回或前进时恢复；虚拟列表把位置交给 `initialOffset`                                                                 |
| 保持页面不卸载                                                                                           | 适合 Viewer 这类覆盖层，不适合相册页、地图页这类独立页面                                                                                       |

### 1.3 实现

[useMasonryScrollRestoration](../../web/components/gallery/hooks/use-masonry-scroll-restoration.ts) 在 [PhotoMasonry](../../web/components/gallery/photo-masonry.tsx) 中调用，返回值作为 TanStack 的 `initialOffset`。

1. **保存。**瀑布流布局就绪后监听滚动，把 `scrollTop` 与 `columnWidth / columnCount` 存进模块级 `Map`，键是挂载时的 `pathname + search`。监听放在 layout effect 中：卸载时它先于下一页把共享滚动元素滚到顶部或被内容收缩截断而移除，不会把 0 写进去。
2. **判断是否为返回或前进。**模块级的 `popstate` 监听记下目标页面键；Viewer 引起的历史跳转除外（见 1.4）。
3. **恢复。**瀑布流首次渲染时读取这个标记和保存的位置；`initialOffset` 按新旧 `columnWidth / columnCount` 的比例换算后交给虚拟列表。虚拟列表第一次启用时直接按这个偏移计算渲染范围，挂载滚动元素时自己滚到该位置。
4. **新访问清理。**不是返回而挂载时，删除该页面键下旧的保存位置。

适用于所有使用 `PhotoGallery` 的页面，相册详情页也会按自己的路径恢复。

### 1.4 实现中确认的四个约束

**必须用 `initialOffset`，不能在 effect 里自行滚动。**TanStack 在挂载滚动元素时（`_willUpdate` 末尾）会执行 `_scrollToOffset(getScrollOffset())`，而 `getScrollOffset()` 返回渲染时缓存的偏移，默认来自 `initialOffset = 0`。第一版在 layout effect 中调用 `scrollTo(3000)`，日志确认位置和标记都正确，随后仍被 TanStack 滚回 0。改为 `initialOffset` 后，恢复由 TanStack 完成，同一次提交里就渲染了目标范围；逐帧记录显示返回后第一帧已在目标位置，可见 17 张卡片，没有空白帧。

**`popstate` 监听必须注册在捕获阶段。**Next 的 `popstate` 处理在 `startTransition` 中派发返回导航，React 19 会同步渲染 `popstate` 中的过渡，所以普通监听执行时，目标页的瀑布流已经挂载。实测第一版因此把返回误判为“瀑布流仍在挂载中”。在 window 上以 `{ capture: true }` 注册后，按 DOM 规范它会先于 Next 的冒泡阶段监听执行；即使 Next 改为异步渲染，顺序也不受影响。

**按目标地址识别 Viewer 的历史跳转。**Viewer 打开时 `pushState` 到 `/photos/…`，关闭时 `history.back()` 回到瀑布流所在页面，浏览器前进又会回到照片地址，这些跳转都不会重新挂载瀑布流，也不应记标记，否则标记会残留并在下一次链接进入首页时被误用。识别条件是：有瀑布流挂载，并且目标地址是它所在的页面或照片路径。

第一版用“当前是否有瀑布流挂载”来判断，代码评审指出它会误伤两个都有瀑布流的页面之间的返回：例如相册详情 → 点 Home → 返回，`popstate` 时首页瀑布流还在，返回被当成 Viewer 关闭，相册详情不恢复，保存的位置还被删除。改为按目标地址判断后，这条链路已实测通过。

**页面键要在 layout effect 中读取，不能在渲染时读取。**点链接导航时，Next 在渲染新页面之后才更新地址；渲染阶段读到的仍是上一页地址。精简代码时曾把读取移到 `useState` 初始化里，回归中出现了“新首页记录返回时被恢复到旧位置”的问题：旧位置没被清理，新位置也存到了上一页的键下。改回在 layout effect 中读取后恢复正常。是否恢复的判断仍在首次渲染时读取，因为返回时地址在 `popstate` 时就已更新。

### 1.5 取舍

- **按路径而不是按历史记录保存。**`history.state` 由 Next 管理并可能被覆盖，不在其中写自定义键。代价是同一路径在历史中出现两次时共享一个位置，影响很小。
- **只保存在内存中。**整页刷新后不恢复，覆盖不了“刷新相册页后再返回”的情况。
- **宽度变化时按比例换算。**瀑布流总高度约等于 `Σ(columnWidth / aspectRatio) / columnCount`，所以位置按 `columnWidth / columnCount` 缩放。只有宽度完全不变时恢复是精确的；宽度一变，即使列数不变，4 px 图片间距和顶部 48 px 留白也不随比例缩放，结果是近似值。
- **照片直达页。**挂载时的键是 `/photos/…`，关闭 Viewer 后地址被 `replaceState` 改成 `/`，返回时键不一致，因此不恢复，按顶部显示。

### 1.6 实测

本机生产构建、内置 Chromium。重复构建后，浏览器缓存中旧构建的页面会引用旧代码块，导致同一页面同时加载两份画廊模块、各有一份模块状态，测试结果失真。最终验证换用新端口（新源、空缓存）进行，所有导航都确认在同一文档内完成。

## 2. 无障碍细节

### 2.1 列表补 `role="list"`

Tailwind preflight 给 `ul` 设置 `list-style: none`，Safari 和 VoiceOver 会因此不再把它当作列表，[057 号文档](057-首页瀑布流前端性能与规范优化.md)中加的 `aria-posinset`/`aria-setsize` 可能不会被读出。`<ul>` 显式加上 `role="list"`。读屏效果尚未用 VoiceOver 验证。

### 2.2 键盘聚焦时显示卡片信息

卡片信息层和图片放大原来只在 `group-hover` 时出现，键盘 Tab 到卡片只能看到焦点框。[PhotoMasonryItem](../../web/components/gallery/photo-masonry-item.tsx) 为信息层加上 `group-focus-visible:opacity-100`，为图片加上 `group-focus-visible:scale-105`，并同样遵守 `motion-reduce`。实测 Tab 到第一张卡片后，信息层 `opacity` 为 1，图片 `scale` 为 1.05。

不支持悬停的设备不渲染信息层，这一点不变；有键盘的设备通常也支持悬停，信息层本来就会渲染。

### 2.3 `HEADER_HEIGHT` 注释

`HEADER_HEIGHT = 48` 与 Header 的 `h-12`、画廊的 `pt-12` 是同一个值，补注释说明，避免以后只改一处。
