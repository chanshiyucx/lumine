# Viewer 缩略图悬浮预览优化方案

- 日期：2026-10-01
- 状态：已实施并完成浏览器验证
- 基线：`1be3128`
- 来源：[Viewer 与 Afilmory 设计对比分析](050-Viewer与Afilmory设计对比分析.md)第三项，选为第二个优化候选
- 约束：改善已有交互与呈现；交互流畅度优先；不增加失败占位或重试

## 选择：悬浮预览延迟 100ms 打开

现有大图预览继续保留，鼠标在同一张缩略图上停留约 100ms 后再打开，离开则立即关闭。缩略图点击仍立即选图，不经过这个延迟。

收益集中在桌面浏览：鼠标快速经过多张缩略图时，减少大预览反复出现和消失，以及随之发生的测量、状态更新与预览图片短暂挂载。移动端当前没有悬浮预览，此项不改善移动手势。

## 优化前的源码证据

- `web/components/viewer/thumbnail-rail.tsx` 的 `onMouseEnter` 立即调用 `updateHoverPreview`；该函数读取 shell 和 button 的 `getBoundingClientRect()`，计算预览尺寸，再设置 `hoverPreview`。
- 只要 `hoverPreview` 非空，就渲染现有预览容器和 `ThumbnailImage`，其中包括 ThumbHash 图片与缩略图。离开按钮或滚动时立即清空状态。
- 因而快速掠过也会执行定位计算并尝试显示预览。这是当前执行路径的事实，不等于已证实它导致了可感知卡顿。
- Afilmory 的 `GalleryThumbnail.tsx` 使用 `HoverCard openDelay={100} closeDelay={0}`，缩略图自身通过 `hover:grayscale-0` 即时恢复彩色。

借鉴的是打开时机，保留 Lumine 当前的宽高限制、横向边界约束、布局及动画。没有必要引入 HoverCard 包装、Portal、标题、日期或新的选中装饰。

## 最小方案：只改 `thumbnail-rail.tsx`

### 1. 用一个局部定时器延迟现有操作

新增 `HOVER_PREVIEW_OPEN_DELAY = 100` 和一个定时器 ref，继续使用现有 `hoverPreview` 状态。

1. 鼠标进入时沿用现有桌面与输入设备判断，取消上一次等待，再设置一个 100ms 定时器。
2. 在事件处理时保存 `event.currentTarget`，不要在异步回调里读取事件的 `currentTarget`。
3. 等待结束后确认按钮仍连接且仍被悬停，再调用现有定位与显示逻辑。布局测量放在这一步，使用当时的位置。
4. 现有 `clearHoverPreview` 同时取消等待并清空已显示的预览；继续由鼠标离开和 rail 滚动触发。
5. 沿用现有切换到移动断点的清理逻辑，将尚未执行的定时器一并取消；卸载时也取消定时器，卸载清理不更新 React 状态。

组件同时最多只有一个等待中的定时器。ref 只持有定时器句柄；不增加 pending/open/closing 状态、操作编号、输入锁、指针轨迹判断或全局监听器。定位计算继续留在当前模块，不提取通用悬浮管理 hook。

### 2. 保留缩略图自身的即时反馈

当前灰度条件依赖 `hoverPreview.index`，直接延迟预览会让缩略图恢复彩色也延迟。将鼠标悬浮时的彩色反馈交给现有按钮的 `lg:hover:grayscale-0`；桌面断点限定与预览启用范围保持一致，非当前照片仍保持默认灰度，当前照片仍保持彩色。

这样可以删除仅用于灰度条件的 `isHover` 派生值，不为“鼠标已进入但预览尚未打开”新增 React 状态。已有 300ms filter 过渡参数保持原样，彩色过渡仍在鼠标进入时开始。

## 成本与取舍

- 停留查看预览会比现在晚约 100ms，这是明确的响应时间取舍；点击选图与照片缩放不受此延迟影响。
- 新增一次等待及取消操作，换取短暂经过时不执行预览定位、也不提交非空预览状态。离开时现有清空调用仍可能执行，不声称消除了所有 React 工作。
- 不新增 DOM；停留后呈现与原先相同的预览。缩略图列表、虚拟滚动、自动居中及图片资源策略保持原样。
- 同一图片可能已通过 rail 请求并缓存；减少预览挂载不等于减少同等数量的网络下载，更不能直接推导帧率提升。
- 首次 ThumbHash 生成可能已有缓存命中，因此实际性能收益取决于浏览路径。此项主要改善快速掠过时的呈现稳定性，预期性能收益是附带收益。

## 验证与采纳标准

| 场景                                    | 应有结果                                                 |
| --------------------------------------- | -------------------------------------------------------- |
| 同一缩略图停留超过 100ms                | 原有预览出现，尺寸和边界定位正确                         |
| 进入后不足 100ms 即离开，或快速扫过多项 | 中间项不显示预览，不提交非空预览状态；最终停留项正常打开 |
| 离开已显示预览的缩略图                  | 立即关闭，无关闭延迟                                     |
| 等待或显示期间滚动 rail                 | 取消等待并关闭预览，不在滚动后突然弹出旧项               |
| 等待期间切换移动断点或关闭 Viewer       | 取消等待，无过期预览；回到桌面可正常再次悬浮             |
| 悬浮、点击、键盘切图                    | 缩略图彩色反馈即时启动；点击和键盘导航不等待 100ms       |
| 横图、竖图和 rail 两端照片              | 保持现有尺寸上限及横向约束                               |

实施时检查正常 DOM、原有样式与动画参数保持一致，并执行相关静态检查。可用临时观察记录比较快速扫过时预览的挂载次数，不在产品代码中保留监测逻辑；没有性能录制就不写帧率或耗时提升结论。

若实际使用觉得 100ms 等待降低了预览体验，应撤回此项，而不是继续增加“已打开后快速切换”等特殊规则。这个候选价值有限但范围清晰，不应为了优化而扩展成完整悬浮机制。

## 实施与验证记录

- 业务代码仅修改 `thumbnail-rail.tsx`：增加一个定时器 ref 和取消方法；测量与设置预览放到延迟回调；断点变化和卸载复用 effect cleanup 取消等待。没有新增 React 状态、DOM 或依赖。
- 删除灰度条件对 `hoverPreview.index` 的依赖，使用桌面断点限定的 CSS hover 保留即时彩色反馈，窄窗口鼠标悬浮仍沿用原有灰度。预览原有尺寸计算、容器、图片、动画，以及点击、虚拟滚动和自动居中逻辑均保留。
- `pnpm lint`、`pnpm type-check`、相关文件 Prettier 与 Git 差异检查通过。命令使用本机 Node 22.23.2，pnpm 提示项目声明 Node >=24；未在 Node 24 下重复检查。
- Chrome 原生鼠标输入：连续掠过四张缩略图，每项停留约 8–14ms，临时 DOM 观察记录预览挂载次数为 0；停留时两次记录的打开时间约为 102–104ms。此数据验证打开时机，不代表帧率提升。
- 等待约 16ms 时读取按钮样式，灰度已开始下降且预览尚未挂载；确认彩色反馈无需等待大预览打开。离开原项时旧预览立即消失。
- 在等待期间滚动 rail，鼠标仍位于 rail 内，预览没有出现；切换到 390×844 移动断点后无预览，恢复桌面后重新悬浮正常。
- 最终 CSS 在 800px 窄窗口鼠标下核查：按钮确实处于悬浮状态，仍为 `grayscale(1)` 且无预览，保持原有断点行为。
- 在 100ms 等待结束前点击缩略图，活动照片和 URL 已变更；方向键切图正常。从画廊打开 Viewer 后，在等待期间按 Escape，返回画廊且预览挂载次数为 0。
- 最终检查已加载预览的透明度为 1、图片完成加载，位置在媒体区域内。使用临时观察器验证，未在产品中保留监测逻辑；已清理测试标签页并恢复浏览器视口。
- 浏览器验证以桌面鼠标和断点切换为主；未新增测试文件，未做真机触摸、完整横竖图边界或帧率对照测试。预览几何算法通过源码差异确认保持原样。

### 代码风格复核

- 取消定时器函数只读取稳定的 ref，移除新增的 `useCallback`；清理 effect 依赖收窄为 `isMobile`。旧闭包与新闭包都访问同一个 ref，不依赖 React Compiler 保证正确性，也不禁用依赖检查。
- 原有 `getItemKey` 的 `useCallback` 保留：当前 TanStack Virtual 将函数引用作为测量选项的缓存依赖，稳定引用有明确消费者。
- 将延迟打开入口命名为 `scheduleHoverPreview`，准确区分安排等待与实际显示。其他定位计算、样式、取消规则和组件组织保持原样。
- 此轮精简已重新通过目标文件 ESLint、TypeScript、Prettier 与差异检查，未重复上一轮浏览器验证。

### 单文件结构整理

- 删除悬浮预览中的 `relative size-full` 包裹层；已有外层绝对定位容器直接容纳 `ThumbnailImage`，预览少一个 DOM 元素。
- 将原有 `getHoverPreviewSize` 扩展为私有纯函数 `getHoverPreviewLayout`，统一计算 `left / width / height`。视口高度和相对中心位置显式传入，不读取 DOM 或 `window`；未增加函数数量或拆出新文件。
- 延迟回调仅负责检查目标、读取位置、调用计算并更新状态；保留原有取整顺序、尺寸约束和边界留白。
- 固定高度常量去掉 `FALLBACK`；ref 集中声明，取消、安排、关闭和清理预览的逻辑放在一起。没有新增 hook、状态、缓存或交互规则。
- 用临时脚本直接提取修改前后的函数与定位表达式，对照 1,225 组比例、容器宽度、视口高度和边界位置输入，`left / width / height` 均精确一致；未留下测试文件。
- Chrome 原生鼠标输入复核：快速扫过无预览挂载，停留约 103ms 后打开；预览直接子元素为 `span`，内部无额外 `div`，两张图片的边界一致。左端和右端分别保留 12px 留白。
- 滚动取消等待、390×844 移动断点清理及恢复桌面后的方向键切图正常。图片填充、尺寸与边界通过 DOM 和截图核查；未做帧率对照或完整真机触摸测试。
- 已重新通过全量 ESLint、TypeScript、相关文件 Prettier 和差异检查；测试观察器、标签页和临时视口均在验证后清理。
