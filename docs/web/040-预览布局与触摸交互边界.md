# 预览布局与触摸交互边界

- 日期：2026-09-26
- 状态：已实施；尚未完成真实 iPad Safari 交互验收
- 范围：预览切图、图片平移、导航按钮，以及跨布局断点时的信息面板状态

## 问题

宽屏 iPad 使用桌面布局，但仍以触摸为主要输入。此前轮播把 `isMobile` 加入 `allowTouchMove` 条件，导致宽度达到 1024px 后触摸切图被禁用。图片层同时在桌面布局下默认允许平移，会拦截未放大时的单指滑动；左右箭头又默认透明、依赖 hover 显示。

布局断点只能决定界面如何排列，不能代表设备是否支持触摸。这里保留现有交互结构，明确布局、输入能力与当前交互状态各自的作用。

## 交互规则

| 条件                                                 | 行为                                                   |
| ---------------------------------------------------- | ------------------------------------------------------ |
| 窄屏布局                                             | 信息面板使用移动端呈现，支持现有上下滑动操作。         |
| 宽屏布局                                             | 信息面板使用右侧栏，包括宽屏 iPad。                    |
| 预览已进入可交互状态、图片未放大、窄屏信息面板未打开 | 所有布局都允许触摸左右切图。                           |
| 图片已放大                                           | 禁用触摸切图，单指拖动用于图片平移。                   |
| 图片未放大                                           | 禁用图片平移，让单指横滑交给轮播。                     |
| 窄屏信息面板打开                                     | 暂停触摸切图。                                         |
| 宽屏信息面板打开                                     | 不影响触摸切图。                                       |
| 宽屏且具备 hover 能力                                | 鼠标悬停或键盘聚焦时显示可用的左右箭头。               |
| 窄屏或不具备 hover 能力                              | 隐藏左右箭头，通过触摸滑动、缩略图或现有键盘导航切图。 |

箭头按 CSS 媒体查询反映的 hover 能力显示，不通过 iPad、手机或桌面设备名称识别输入方式。

## 组件职责

[Viewer](../../web/components/viewer/viewer.tsx) 组合布局和面板状态，在此处把窄屏面板状态转换为轮播限制：

```tsx
isSwipeDisabled={isMobile && mobile.infoOpen}
```

这样即使窄屏打开面板后旋转或调整窗口进入宽屏布局，保留的 `mobile.infoOpen` 也不会继续禁止滑动。关闭宽屏侧栏只改变桌面面板状态；回到窄屏时沿用原有移动端面板状态，无需额外 effect 清空它。

[PhotoCarousel](../../web/components/viewer/photo-carousel.tsx) 根据可交互状态、缩放状态和上层提供的滑动限制决定 `allowTouchMove`，不再依据布局宽度禁止原生触摸滑动。`simulateTouch={isMobile}` 保留原有鼠标模拟拖动策略；该参数不禁用原生触摸事件。

[ZoomableImage](../../web/components/viewer/zoomable-image.tsx) 仅根据自身缩放状态启用图片平移，不订阅布局断点。[ViewerNavigation](../../web/components/viewer/viewer-controls.tsx) 使用 CSS 控制箭头显示，在 `hover: none` 时设为 `display: none`，避免留下透明但可点击的按钮。

这些条件直接从已有状态计算，不增加设备检测、全局状态、手势协调层或状态同步 effect。

## 与 Afilmory 的关系

参考对象为 `tmp/afilmory/apps/web/src/modules/viewer/PhotoViewer.tsx`。

- 核心触摸切图规则对齐：不因宽屏布局关闭触摸导航；图片放大后暂停切图；面板限制只作用于窄屏布局。
- 箭头处理不同：Afilmory 在宽屏布局仍渲染默认透明的箭头，通过 hover 显示；本项目在无 hover 能力时直接隐藏。
- 图片平移不同：Afilmory 在桌面布局默认允许平移；本项目在所有布局下都要求图片已放大，把未放大时的横滑交给轮播。
- 鼠标模拟拖动配置不同：Afilmory 未覆盖 Swiper 默认值；本项目继续保留 `simulateTouch={isMobile}`。

目标是保留适合本项目的交互分工，并非逐项复制 Afilmory。两者使用的 Swiper 版本也不同，不能仅凭参考项目推断浏览器手势已经验证通过。

## 验证边界

本轮不新增自动化测试，并移除此前新增的 VM 配置测试。该测试只检查传入 mock 组件的 props，不运行浏览器事件或 effects，不能作为真实滑动已经通过的证据。

真实设备验收仍需覆盖：

1. 宽屏 iPad 打开包含多张照片的预览，确认箭头隐藏、左右滑动可以切图。
2. 放大后确认拖动平移图片、不会切图；恢复后确认滑动切图恢复。
3. 窄屏打开信息面板后旋转到宽屏，确认滑动可用，且不受侧栏开关影响。
4. 返回窄屏后确认面板状态与滑动限制一致。
5. 鼠标设备确认箭头悬停显示、点击和键盘导航可用。
