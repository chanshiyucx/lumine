# 照片按拍摄地时区展示

## 背景与约定

索尼相机一直使用北京时间，照片记录带 `+08:00`；iPhone 记录当地时间并带对应偏移。两者的 `takenAt` 都已经表示正确的拍摄时刻，只需要转换展示时区，不需要按设备区分修正。

例如 `2024-11-16T17:56:23+08:00` 与 `2024-11-16T10:56:23+01:00` 是同一时刻，在 `Europe/Berlin` 中都显示为 `2024/11/16 10:56:23`、`UTC+1`。

前提是 `takenAt` 带有正确偏移。无偏移、偏移标注错误或相机钟点错误，属于源数据问题，本方案不推断或修正。不修改 pipeline、manifest 或照片文件，不增加日期库、第三方查询服务或测试文件。

## 手工配置

沿用 `map.json` 的版本 1，在每个相册地点上增加可选 `timeZone`：

```json
{
  "version": 1,
  "locations": {
    "20241116-Barmsee": {
      "lat": 47.5001,
      "lng": 11.247,
      "timeZone": "Europe/Berlin"
    }
  }
}
```

填写拍摄地的有效 IANA 时区名称，不保存固定小时差。`Intl.DateTimeFormat` 根据拍摄日期处理夏令时；浏览器原生 API 不负责从经纬度查找时区。

本次已补齐 `/Volumes/Xin T7/R2/map.json` 中全部 22 个相册：长沙为 `Asia/Shanghai`，德国地点为 `Europe/Berlin`，巴黎为 `Europe/Paris`，西班牙地点为 `Europe/Madrid`，意大利地点为 `Europe/Rome`，杜布罗夫尼克为 `Europe/Zagreb`，库夫施泰因为 `Europe/Vienna`。

一个相册使用一个时区；跨时区旅行需按地点拆分相册。无地点条目或无 `timeZone` 时保留原记录时间与偏移。地图配置仍然可选：HTTP 404 返回空地点表；其他请求、JSON 或结构错误继续报错，不静默吞掉。

## 数据与展示链路

`lib/album/locations.ts` 承担共享地点读取、结构校验与相册键归一化。它不依赖相册目录或照片集合，避免形成循环依赖。使用 `React.cache` 复用请求内解析结果，沿用 30 秒 fetch 重验证。

`getPhotoCollection` 并行读取 manifest 和地点表，按相册键取得时区，调用 `photo/capture-time.ts` 的 `formatCaptureTime` 一次性生成 `Photo.captureTime`，包含 `date`、`dateTime` 和 `timeZone`。这是前端展示模型的派生字段，不写回 manifest。地图展示复用同一个 `getAlbumMapLocations`，浏览器无需另行请求配置。

`photo/capture-time.ts` 使用显式 locale、拍摄地时区与 24 小时制，通过 `formatToParts` 提取日期、时间和当天的 UTC 偏移。没有相册时区时，使用已经通过 manifest 校验的 `takenAt` 原始偏移作为展示时区；由同一个实现处理两种情况，不保留额外正则解析和 Unknown 分支。按时区复用格式化器；缓存仅保存无请求状态的格式化器，不保存照片数据。展示不使用访客或服务器的默认时区。

三个调用方直接读取统一生成的标签，不再调用日期格式化或时区转换；滚动更新首页标题时也不重复计算。`lib/date.ts` 只负责相册的纯日期格式化，不暴露照片时区处理的内部工具。

应用范围：

- 照片详情中的 Taken At 和 Time Zone。
- 首页随当前照片变化的日期。
- 照片分享图片中的日期。

跨午夜的转换会同步更新日期。未配置时区时，照片分享图片也保留原记录日期，与首页一致，替代此前固定按 UTC 显示的逻辑。

照片排序继续按原始 `takenAt` 的时间戳倒序；相册页与地图上的相册日期仍来自文件夹名称，属于相册标识，不做时区转换。

## 设计复核

- `locations.ts` 负责相册地点配置，包括坐标与时区；`map.ts` 负责组装地图展示模型，两个模块职责分开。
- 照片时间转换集中在一个函数，内部格式化器与分量提取不对外暴露。日期、时间、偏移都由同一拍摄时刻生成，避免字符串重建后再解析。
- 服务端生成标签使首页、详情和分享图消费同一结果，避免浏览器与服务端时区数据库差异造成不一致。代价是每张照片向客户端多传三段展示文本；本站 locale 固定且照片模型本来就包含派生字段，因此接受这个明确的小额传输成本，不增加多语言模型或标签缓存层。
- `takenAt` 仍然保留原始时刻并用于排序；展示标签不参与业务比较。未来若支持访客自选时区或语言，应重新评估标签的生成位置，而不是继续扩展固定标签字段。

## 验证与上线

不增加测试文件。使用格式检查、lint、TypeScript 检查、已有测试，以及一次性运行校验验证冬夏令时、切换边界、跨日、混合设备记录和缺省配置。

实施后验证结果：

- Prettier、lint、类型检查和已有的 2 个测试通过。
- 使用 Node 24 与本地媒体目录完成生产构建，30 个静态页面生成成功。
- 12 组时间转换校验通过，覆盖冬夏令时及切换边界、跨日、索尼/iPhone 同一时刻、缺省时区、零偏移和非整小时偏移。
- 22 个时区配置有效，全部 459 张照片通过相册键匹配与详情、首页日期格式化校验。Königssee 的组合字符差异通过现有 NFC 归一化处理。
- 生产首页 HTML 已包含派生的拍摄时间展示标签，确认统一结果进入前端展示链路。

本地 `map.json` 在仓库外，需按现有流程同步到 `MEDIA_ORIGIN` 才能让线上前端读取。部署前端后，地点配置沿用 30 秒重验证机制；外部 CDN 的缓存更新仍按现有同步流程处理。
