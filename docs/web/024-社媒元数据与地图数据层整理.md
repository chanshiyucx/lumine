## 社媒元数据

新增 `web/lib/page-metadata.ts`，集中维护两项导出：

| 导出 | 职责 |
| --- | --- |
| `socialMetadata` | 默认 Open Graph 站点名称、网站类型、描述，以及 Twitter 大图卡片类型和描述 |
| `createPageMetadata(title)` | 为详情页生成页面标题及带完整共享字段的 Open Graph、Twitter 配置 |

根布局展开 `socialMetadata`，继续维护 `metadataBase`、页面标题模板、描述等站点设置。相册与照片详情页在加载路由资源后调用 `createPageMetadata()`，不再分别维护同一套社媒配置。

### 为什么显式合并

Next.js 在路由段之间对 Metadata 做浅合并。子页面声明 `openGraph: { title }` 时，会替换父级整个 `openGraph` 对象，不能依赖它继承 `siteName`、`type` 等字段；`twitter` 也应按同样原则处理。因此，工厂分别展开共享对象，再设置页面标题。

根级社媒配置不固定 `title`。当前 Next.js 会从最终页面 Metadata 补全缺失的社媒标题，因此首页使用站点标题，相册列表和地图页使用各自经过页面标题模板解析的标题。详情页继续显式使用资源标题作为分享标题。

`siteConfig.locale` 当前为 HTML 语言代码 `en`，并未指定地区。本次不直接把它作为 Open Graph 的 `locale`；如果以后需要该字段，应独立配置符合 `language_TERRITORY` 格式的实际站点区域值。

### 分享图片

保留已有文件式图片入口：

- `web/app/opengraph-image.tsx`
- `web/app/albums/[albumKey]/opengraph-image.tsx`
- `web/app/photos/[photoId]/opengraph-image.tsx`

共享配置不声明 `images`，图片仍由 Next.js 文件式 Metadata 管理。当前版本在没有独立 Twitter 图片时会从 Open Graph 补全图片。本次是补全默认字段与消除重复配置，不是首次加入分享图片支持。

参考：[Next.js Metadata 合并规则](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#merging)。

## 地图数据模块

将 `web/components/map/lib/album-map-data.ts` 移到 `web/lib/album-map.ts`，与 `album-catalog.ts` 等数据模块保持一致。

| 模块 | 职责 |
| --- | --- |
| `web/lib/album-map.ts` | 请求并校验 map JSON、加载相册目录、聚合地图展示数据和导出数据类型 |
| `web/app/map/page.tsx` | 服务端调用 `getAlbumMapItems()`，向组件传递结果 |
| `web/components/map/` | 地图加载、交互和展示，通过 `import type` 引用数据类型 |

保留 `server-only`、React 请求缓存、30 秒 fetch 再验证、并行加载、Zod 校验及封面选择逻辑。组件不导入服务端函数；类型导入会在编译时擦除。类型暂时与数据生成函数放在同一模块，不额外引入接口层。

这是目录组织的一致性调整，原有服务端与客户端运行边界已经成立，不预期改变数据或性能行为。
