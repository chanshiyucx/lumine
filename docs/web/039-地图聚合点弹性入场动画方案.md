# 地图地点标记弹性入场动画方案

- 状态：已实施，已完成浏览器回归
- 日期：2026-09-25
- 范围：地图聚合标记的身份，以及聚合标记与单个相册标记的入场动效

## 问题与目标

地图重新计算聚合后，新出现的聚合点和单个相册地点会直接以最终尺寸显示。尤其在首次打开地图、缩放结束或展开一个聚合点后，这种瞬间出现显得生硬。参考 afilmory 的聚合标记，本方案让**新挂载的地点标记**从中心放大，略微超出最终尺寸后回落。两类标记共用 340ms 动画。

固定或取消固定某个相册会重建 Supercluster 索引。此时地图上其他区域的聚合点可能仍代表同一批相册，却拿到新的 `cluster_id`。入场动画若直接绑定现有 React key，会使这些无关聚合点一起重播。实施动效前，必须先让聚合标记拥有跨索引重建的稳定身份。

聚合算法、展开方式、封面加载和预览卡行为沿用现状。不增加聚合点之间的位移动画、消失动画或持续脉冲。

## 已核实的现状

- `AlbumMap` 在地图移动结束后更新视口，并以 `cluster-${clusterId}` 为聚合标记的 React key。[地图组件](../../web/components/map/album-map.tsx)
- `prepareAlbumMapSelection` 在 `pinnedAlbumKey` 变化时剔除已选相册并重建索引。[选中逻辑](../../web/components/map/lib/album-map-selection.ts)
- Supercluster 8 的内部 `cluster_id` 包含输入点数量；输入点数量变化时，即使远处聚合的成员完全相同，其 ID 也可能变化。用三个城市各两个点的最小样例验证：固定罗马一个点后，巴黎聚合 ID 从 `82` 变为 `49`，东京从 `146` 变为 `113`，而两处的成员均未变化。`cluster_id` 仍应用于 `getLeaves` 和展开计算，但不能单独用作 React 标记身份。
- `ClusterMarker` 的触发元素是固定宽高的按钮，按钮内有光晕、封面和数量。现有 `group-hover:scale-105` 只处理悬停。[标记组件](../../web/components/map/album-map-marker.tsx)
- MapLibre 的 `Marker` 外层使用 `transform` 定位地理坐标；Radix HoverCard 以按钮作为定位锚点。入场缩放只能作用于按钮内的视觉内容，不能作用于 MapLibre 外层或按钮本身。[悬停预览](../../web/components/map/map-hover-preview.tsx)

## 交互规格

| 场景                                 | 期望行为                                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 首次进入地图                         | 聚合点和单个相册点从中心弹出；聚合点的光晕、封面和数字同步缩放。                                      |
| 缩放产生新聚合点                     | 新身份的聚合点播放一次入场；同身份聚合点不重播。                                                      |
| 缩放产生单个相册点                   | 新挂载的相册点播放一次入场；已有相册点更新位置或属性时不重播。                                        |
| 平移后重新进入视口                   | 若原标记已经卸载，重新挂载时播放入场；仍在 React 树中的标记不重播。                                   |
| 固定或取消固定相册                   | 与该相册无关、成员未变的聚合点保持 DOM 身份，不重新弹跳；受影响的聚合点按其新身份或原有身份正常更新。 |
| 聚合数量、封面或坐标变化，但身份未变 | 更新内容或位置，不重播入场。                                                                          |
| 悬停或点击聚合点                     | 保持原有放大、预览和展开行为；按钮尺寸及命中区域不随入场缩放改变。                                    |
| `prefers-reduced-motion: reduce`     | 两类标记直接以最终尺寸出现。                                                                          |

这里的“新身份”由当前整数缩放级别与聚合成员中**字典序最小的相册 key**组成，而非由 Supercluster 的内部 ID 决定。同一缩放级别下，各聚合的成员互不重叠，因此最小成员 key 不会在两个聚合点之间重复。相册被移除后，若某个聚合的最小成员未变，该标记会被复用，数量可以直接更新；若最小成员变化，该聚合重新入场。无需为每一次成员变化强制播放动画。

## 实现方案

### 1. 生成稳定的聚合标记 key

为 Supercluster 增加 `map` / `reduce` 聚合属性，在构建索引时计算每个聚合的 `minAlbumKey`。用字符串 `<` 比较，结果只由聚合成员决定，不依赖输入顺序、叶子遍历顺序或 `cluster_id`。在 `AlbumMap` 中把 React key 改为 `cluster-${viewport.zoom}-${minAlbumKey}`；`clusterId` 仍用于现有 `getLeaves`、`getClusterExpansionZoom` 和点击回调。

结构示意：

```tsx
interface ClusterIdentity {
  minAlbumKey: string;
}

new Supercluster<AlbumPointProperties, ClusterIdentity>({
  radius: CLUSTER_RADIUS,
  maxZoom: MAX_CLUSTER_ZOOM,
  map: ({ item }) => ({ minAlbumKey: item.key }),
  reduce: (accumulated, next) => {
    if (next.minAlbumKey < accumulated.minAlbumKey) {
      accumulated.minAlbumKey = next.minAlbumKey;
    }
  },
}).load(points);

// 在聚合 feature 分支内；clusterId 继续用于查询和展开
const markerKey = `cluster-${viewport.zoom}-${feature.properties.minAlbumKey}`;
```

不能只采用 `clusterItems[0]?.key`：现有 `getLeaves` 只取预览容量内的前几个叶子，其顺序不是稳定身份契约；索引重建后即使聚合成员相同，首个叶子也可能变化。也不应为生成 key 对每个可见聚合调用 `getLeaves(clusterId, Infinity)` 并排序；在索引构建时归约一个最小 key 即可得到与成员数量无关的常数大小属性。

### 2. 两类标记共用 CSS 一次性弹性入场

在 `ClusterMarker` 按钮内部增加一个 `relative block size-full` 的 span，包裹现有光晕和主体，使两者一起入场。在 `AlbumMarker` 中直接给现有封面 span 添加 `album-map-marker-visual` 类，无需新增节点。按钮继续作为 HoverCard 的触发元素，保留现有宽高、`aria-label` 和点击处理。相册点的悬停样式使用 CSS 独立的 `scale` 属性，入场关键帧使用 `transform`，两者可以在同一元素上组合；聚合点的悬停与入场仍分属内外两层。固定或取消固定相册沿用同一 React key 和扁平标记数组，不会重播入场。

在现有 [map.css](../../web/app/map/map.css) 用一次性的 `transform: scale(...)` 关键帧，并在 `prefers-reduced-motion: reduce` 下关闭该动画。初始值为 `scale(0)`，中途轻微越过 `1`，随后回落到 `1`。根据实际体验，时长从 420ms 缩短至 340ms，峰值保持 `1.05`。这些是视觉参数，不声称与 afilmory 的物理弹簧逐帧相同。

结构示意，省略原有子节点：

```tsx
<button
  type="button"
  className="group ..."
  style={{ width: size, height: size }}
>
  <span className="album-map-marker-visual relative block size-full">
    {existingRingAndClusterVisual}
  </span>
</button>

<button type="button" className="group relative block size-11">
  <span className="album-map-marker-visual ... group-hover:scale-[1.08]">
    {existingAlbumCoverAndOverlay}
  </span>
</button>
```

```css
.album-map-marker-visual {
  transform-origin: center;
  animation: album-map-marker-in 340ms ease-out both;
}

@keyframes album-map-marker-in {
  0% {
    transform: scale(0);
  }
  68% {
    transform: scale(1.05);
  }
  84% {
    transform: scale(0.985);
  }
  100% {
    transform: scale(1);
  }
}

@media (prefers-reduced-motion: reduce) {
  .album-map-marker-visual {
    animation: none;
  }
}
```

CSS 动画在节点挂载时播放，普通 React 属性更新不会重启它。缩略图或 ThumbHash 占位仍按现有时机显示；入场不等待图片下载。

### 选型依据

项目已依赖 Motion，afilmory 也用 `stiffness: 300`、`damping: 25` 的 Motion spring。若要求与其**物理轨迹逐帧一致**，Motion 更直接。但本需求是让地图上新挂载的聚合点和相册点自然出现，触发条件只有节点挂载。CSS 关键帧足以实现可调的超调与回落，并复用地图页现有 CSS 动效方式；它不增加地图路由的 Motion 运行时代码，也不需要在每个标记上创建 Motion 组件或调用 `useReducedMotion()`。只动画 `transform` 也给浏览器合成优化留出空间，但实际是否由合成线程执行应以性能记录为准，不能保证“完全不占主线程”。因此本方案选择 CSS。若视觉验收发现关键帧无法满足目标，再基于录屏对比考虑 Motion，不预先引入运行时。

## 不采用的扩展

- 不在地图移动的每一帧重新计算聚合；继续在 `onMoveEnd` 更新视口，避免让动效改变地图的数据更新节奏。
- 不使用 `AnimatePresence`、全局“已出现”集合或手工计时器；卸载后重新挂载即入场。
- 不复制 afilmory 的持续脉冲环、按压缩放或聚合形变。
- 不改动单个相册标记的 React key 或扁平标记数组结构。

## 验收方法

1. 为聚合身份增加一个针对真实 Supercluster 索引的回归用例：三个相隔较远的区域各有多个相册，固定其中一处相册并重建索引。断言其他两处的 `cluster_id` 允许变化，但 `minAlbumKey` 与最终 React key 保持一致；取消固定后仍一致。再验证缩放级别变化时 key 变化，同级别的不同聚合 key 不重复。
2. 浏览器首次打开地图，确认聚合点与单个相册标记都从中心弹出，聚合点的光晕、封面和数字同步；地图底图不参与动画。检查关键帧结束后视觉尺寸为原尺寸，无持续抖动。
3. 在一个区域固定及取消固定相册，观察视野内其他无关区域的聚合点：**不得重新缩小或弹跳，也不得重建对应 DOM 标记**。受影响区域的聚合计数与预览叶子仍正确；已选相册标记沿用既有复用行为。
4. 连续缩放、展开及平移地图，确认新聚合点播放一次，未卸载的同身份聚合点不重播；动画过程中聚合按钮可点击，HoverCard 仍锚定固定大小的按钮，动画结束后悬停放大正常。
5. 在浏览器启用 `prefers-reduced-motion: reduce` 后重新进入地图并缩放，确认两类标记直接显示为最终大小；恢复设置后，新挂载的地点标记恢复入场动画。
6. 实施后运行 `pnpm --dir web type-check`、相关测试、修改文件的 ESLint 和 Prettier 检查，并完成上述浏览器交互检查。视觉效果以录屏或实际设备观感验收。

## 风险与边界

- `minAlbumKey` 标识的是当前缩放级别下聚合标记的连续性，不是完整成员集合的指纹。只要最小成员还在，其他成员增减不会触发入场；这是有意选择，用于让已有聚合点安静地更新数量。
- 快速连续缩放时，旧聚合点可能在动画结束前卸载；新缩放层级的聚合点按新 key 入场，无需等待旧动画。
- `transform` 动画通常适合合成，但大量聚合点同时出现时仍需浏览器检查。若出现掉帧，先根据性能记录调整动画长度和曲线，再评估其他实现。

## 实施与验证记录

聚合索引已用 `map` / `reduce` 计算 `minAlbumKey`，聚合标记 key 已改为缩放级别与该值的组合。聚合按钮内增加视觉包装层，单个相册按钮复用原有封面 span；两者共用 `map.css` 中的 340ms 入场关键帧和减少动态效果规则。`both` 填充模式确保动画启动前应用首帧样式。单个相册标记的 key 与扁平标记数组结构没有改动。

真实 Supercluster 回归用例使用罗马、巴黎、东京三组相册：固定罗马相册后，巴黎、东京聚合的内部 ID 变化，但稳定 key 保持一致。项目三项测试、`pnpm type-check`、修改文件的 ESLint 和 Prettier 检查均通过。当前本机 Node 为 22.23.2，低于项目声明的 Node 24 最低版本；正式构建仍应由符合版本要求的 CI 覆盖。

本地地图页浏览器回归：首次视野内的三个聚合点和两个单个相册点均使用 `album-map-marker-in`，计算时长 `0.34s`、填充模式 `both`。固定和取消固定 Paris 相册时，原有地点标记保持 DOM 身份，没有因选中状态重播入场。简化相册点结构后，浏览器确认其原封面 span 是按钮的直接子节点；预览打开时，同一节点同时具有入场动画的最终 `transform: matrix(1, 0, 0, 1, 0, 0)` 与悬停状态的 `scale: 1.08`，取消固定前后的 `backendNodeId` 均为 `303`。模拟 `prefers-reduced-motion: reduce` 时，两类标记的计算动画均为 `none`。
