# 预览组件细节优化 v2

## 背景

上一轮已经完成了预览层 portal、缩略图状态复用和 loading 浮层收紧，但实际体验里还剩下三个明确问题：

1. hover 悬浮预览偶发被主图区原图遮挡
2. 预览层容器虽然用了 `h-full w-full`，但视觉上仍然不像真正以视口为边界铺满
3. 当前预览层仍然在手写 SVG 图标，不利于后续统一风格和维护

## 问题根因

### 1. hover 预览仍然依附在底栏容器坐标系里

上一版虽然已经把 hover 预览从滚动容器里提出来，但它仍然挂在底栏壳容器内部，通过 `bottom-full` 向上浮出。这样一来：

1. 它仍然和底栏本身共享局部层级
2. 容易和主图区里的 WebGL canvas、导航按钮产生层级竞争
3. 在某些合成层场景下，会出现“明明 z-index 更大，但看起来仍然压在原图后面”的问题

### 2. 预览层内部仍然依赖 `h-full` 传递高度

portal 已经把 viewer 挂到 `document.body`，但内部主容器仍然使用：

1. `relative flex h-full w-full flex-col`
2. 由父级一路向下传递 `h-full`

这种写法理论上可行，但在实际布局里不如直接以视口尺寸作为根约束来得稳。尤其是这种全屏预览层，不应该继续依赖中间容器的高度继承链条。

### 3. 手写 SVG 图标不可维护

当前 viewer 里包括：

1. 左右切换箭头
2. 关闭按钮
3. 右侧面板展开 / 折叠图标
4. loading 旋转图标

都还是手写 SVG。这样的问题是：

1. 线宽、尺寸和对齐风格不统一
2. 后续替换图标风格成本更高
3. 每次都要单独维护 SVG 组件，没有必要

## 已实施调整

### 1. hover 预览提升为独立覆盖层

当前 [components/photo/photo-viewer.tsx](/Users/xin/Developer/lumine/components/photo/photo-viewer.tsx) 已将 hover 预览改成 viewer 根节点下的独立绝对定位层：

1. 不再挂在底栏壳容器内部
2. 定位坐标直接基于视口计算
3. 使用更高的 `z-[90]`
4. 悬浮预览始终覆盖在主图区和底栏之上

这直接解决了 hover 浮窗被原图遮挡的问题。

### 2. viewer 根节点改为显式视口尺寸

当前预览层根节点不再仅依赖 `inset-0 + h-full`，而是直接使用：

1. `position: fixed`
2. `width: 100vw`
3. `height: 100dvh`

同时内部主容器改成 `absolute inset-0` 的整屏结构。这样布局边界就直接锚定在视口，不再依赖中间层级是否正确传递 `100%` 高度。

### 3. 全部图标替换为 `lucide-react`

这一轮已新增依赖 `lucide-react`，并替换了预览层中的所有手写 SVG：

1. 左右切换按钮改为 `ChevronLeft` / `ChevronRight`
2. 关闭按钮改为 `X`
3. 右侧信息栏折叠按钮改为 `PanelRightClose` / `PanelRightOpen`
4. loading 图标改为 `LoaderCircle`

## 当前实现说明

### 1. hover 预览的定位改成视口坐标

当前 hover 预览在更新位置时，会直接读取：

1. 当前缩略图按钮的 `getBoundingClientRect()`
2. 底栏壳容器的 `getBoundingClientRect()`
3. 当前视口宽高

最终得到 `left / top / width`，直接在 viewer 根层里绝对定位。因此它现在本质上是一个独立浮层，而不是 rail 的附属节点。

### 2. `100dvh` 是为了移动端和桌面端都稳定

这里没有继续用单纯的 `100vh`，而是显式使用 `100dvh`。这样在带有动态浏览器 UI 的环境里，预览层高度会比传统 `vh` 更稳定。
