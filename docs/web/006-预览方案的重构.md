# 预览方案的重构

## 背景

预览链路上一阶段主要是为了兼容 `HEIF/HIF` 原图，做了两层特殊处理：

1. `/api/photos/[photoId]` 在服务端把 `HEIF` 即时转成 `JPEG`
2. 主图区直接依赖 `@afilmory/webgl-viewer` npm 包

当前素材链路已经变化：

1. `manifest.json` 中原图已统一切换为 `AVIF`
2. 不再需要为 `HEIF` 做额外解码转换
3. 预览查看器后续大概率还要继续二次重构，因此不再适合继续把 WebGL viewer 当外部依赖引用

## 本轮目标

1. 移除上一阶段为 `HEIF` 增加的特殊转码路径
2. 将 `@afilmory/webgl-viewer` 源码直接 vendoring 到项目内部
3. 保持当前预览交互和进度加载能力不回退

## 已实施改动

### 1. 原图代理回到纯透传

当前 [app/api/photos/[photoId]/route.ts](/Users/xin/Developer/lumine/app/api/photos/[photoId]/route.ts) 已经移除 `sips` 转码逻辑。

现在的行为是：

1. 根据 `photoId` 找到原图
2. 从 R2 拉取原图资源
3. 直接按原始 `content-type` 和 `content-length` 透传给前端

因为当前 manifest 中原图已经是 `image/avif`，浏览器端可直接消费，不再需要服务端先转成 JPEG。

### 2. WebGL viewer 已本地化

`@afilmory/webgl-viewer` 的源码已经复制到本地模块：

1. [components/webgl-viewer/webgl-image-viewer.tsx](/Users/xin/Developer/lumine/components/webgl-viewer/webgl-image-viewer.tsx)
2. [components/webgl-viewer/webgl-image-viewer-engine.ts](/Users/xin/Developer/lumine/components/webgl-viewer/webgl-image-viewer-engine.ts)
3. [components/webgl-viewer/texture-worker.ts](/Users/xin/Developer/lumine/components/webgl-viewer/texture-worker.ts)
4. [components/webgl-viewer/constants.ts](/Users/xin/Developer/lumine/components/webgl-viewer/constants.ts)
5. [components/webgl-viewer/types.ts](/Users/xin/Developer/lumine/components/webgl-viewer/types.ts)

8. [components/webgl-viewer/index.ts](/Users/xin/Developer/lumine/components/webgl-viewer/index.ts)

### 3. 为 Next/Turbopack 做了本地适配

复制源码后，做了一个必要调整：

1. 原包内部通过 `?raw` 方式加载 worker 源码
2. 本地模块改成 `new Worker(new URL('./texture-worker.ts', import.meta.url), { type: 'module' })`

这样 worker 可以直接交给 Next/Turbopack 打包，不再依赖包构建阶段的 `vite ?raw` 行为。

### 4. 预览主图区已切到本地模块

当前 [components/photo/photo-progressive-view.tsx](/Users/xin/Developer/lumine/components/photo/photo-progressive-view.tsx) 不再从 npm 包导入 `WebGLImageViewer`，而是直接使用本地模块：

1. 网络进度读取逻辑保留
2. 同源 `/api/photos/[photoId]` 拉取保留
3. 高清图成功加载后仍然优先走 WebGL viewer
4. 失败时依然保留普通图片和缩略图兜底

### 5. 已移除外部依赖

`package.json` 和 `pnpm-lock.yaml` 中的 `@afilmory/webgl-viewer` 已移除，当前 viewer 只依赖本地源码。

## 当前收益

1. 预览架构不再依赖外部包发版
2. 后续可以直接在仓库内修改 WebGL viewer 的任意实现细节
3. 原图链路与素材格式现状一致，不再保留无意义的 `HEIF` 特殊兼容代码

## 后续建议

下一步如果继续重构本地 viewer，优先级建议如下：

1. 将当前 viewer 的调试面板和生产逻辑拆开，避免无关代码一直跟随主模块
2. 评估瓦片系统是否真的需要完整保留，当前图库规模和交互复杂度未必需要这么重的实现
3. 将主图区的加载状态与 viewer 内部 `onLoadingStateChange` 更紧密地接起来，而不是只保留外层的网络进度条
