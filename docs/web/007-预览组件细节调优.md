# 预览组件细节调优

## 背景

上一阶段已经完成了预览层重构和高清图代理，但在交互细节上和目标效果还有明显差距：

1. 预览层偶发看起来没有真正铺满视口，右侧会出现多余留白
2. 底部缩略图仍然有明显的激活 ring / 边框感，不够干净
3. hover 悬浮预览是瞬时出现，缺少进入动效
4. hover 悬浮预览偶尔会先露出 blurhash，而不是直接复用已经加载好的缩略图
5. 右下角原图加载提示偏大，且进度条信息密度不高

## 问题根因

### 1. 预览层没有彻底脱离页面文档流

虽然 [components/photo/photo-viewer.tsx](/Users/xin/Developer/lumine/components/photo/photo-viewer.tsx) 已经使用了 `fixed inset-0`，但组件仍然挂在瀑布流节点树内部。这样会受到祖先层叠上下文、滚动容器和页面布局状态的影响，视觉上更容易出现“没有完全贴住窗口”的错觉或边缘异常。

### 2. 缩略条的状态表达过于依赖边框

上一版通过：

1. `ring-1 ring-white/90 ring-inset`
2. hover / active 时的明显边框层

来标识当前缩略图。这样虽然状态清楚，但和 Afilmory 那种更平的缩略条风格不一致。

### 3. hover 预览没有独立过渡层

hover 浮窗是根据 `hoverPreview` 条件渲染后直接出现的，缺少单独的进入动画，所以从感知上会显得“弹出来”而不是“浮上来”。

### 4. hover 预览没有复用缩略图加载状态

底部缩略图和 hover 浮窗都各自渲染了一套：

1. blurhash 预览图
2. 真实 `thumbnail`

但上一版没有共享“这张缩略图已经加载完成”的状态。结果就是：即使底部缩略图已经完成加载，hover 浮窗还是会先显示一层 blurhash，然后再等自己的 `img` 完成显示。

### 5. 加载提示卡片信息结构偏重

[components/photo/photo-progressive-view.tsx](/Users/xin/Developer/lumine/components/photo/photo-progressive-view.tsx) 之前的 loading UI 是：

1. 大号半透明卡片
2. 标题 + 百分比
3. 长进度条
4. 字节信息

这更像调试面板，不像预览器里的轻量状态提示。

## 已实施调整

### 1. 预览层改为挂载到 `document.body`

当前 [components/photo/photo-viewer.tsx](/Users/xin/Developer/lumine/components/photo/photo-viewer.tsx) 已改为通过 `createPortal()` 挂载到 `document.body`：

1. 预览层不再依附于瀑布流 DOM 结构
2. `fixed inset-0` 直接以视口为参照
3. 主区、右栏、底栏都按整屏布局工作
4. 这也是后续继续做全屏交互时更稳定的结构基础

### 2. 缩略条去掉 ring / 边框型状态

底部缩略图轨道已调整为更平的视觉表达：

1. 当前项不再使用白色 `ring`
2. 缩略按钮不再依赖边框表达状态
3. 当前项和 hover 项主要通过取消灰度、提升不透明度来区分
4. rail 自身也移除了顶部边线，改成更轻的贴底背景层

### 3. hover 悬浮预览增加进入动效

当前 hover 浮窗使用了新的 `viewer-hover-preview` 动画：

1. 从 `translateY(10px) + scale(0.985)` 进入
2. 同时做透明度淡入
3. 动画时长为 `220ms`
4. 缓动为 `cubic-bezier(0.16,1,0.3,1)`

对应 keyframes 定义在 [styles/globals.css](/Users/xin/Developer/lumine/styles/globals.css)。

### 4. hover 浮窗复用已加载缩略图状态

当前 [components/photo/photo-viewer.tsx](/Users/xin/Developer/lumine/components/photo/photo-viewer.tsx) 新增了 `loadedThumbnailUrls` 状态集合，用来统一记录哪些缩略图已经成功加载：

1. 底部缩略图 `img` 加载完成后会登记到集合里
2. hover 浮窗渲染同一张图时，先检查该 URL 是否已加载
3. 如果已经加载，则直接显示真实缩略图，不再显示 blurhash
4. 如果还没加载完成，才临时显示 blurhash 作为兜底

这样 hover 预览不会再因为重复挂载新的 `img` 节点，而在视觉上闪出不必要的模糊占位。

### 5. 右下角加载提示改为紧凑模式

当前 [components/photo/photo-progressive-view.tsx](/Users/xin/Developer/lumine/components/photo/photo-progressive-view.tsx) 的加载提示已改成更接近参考实现的轻量结构：

1. 左侧为旋转 loading 图标
2. 右侧第一行只显示当前进度百分比
3. 右侧第二行显示已加载体积 / 总体积
4. 去掉长进度条
5. 整体尺寸压缩为小型浮层，不再占用过多视觉权重

## 当前实现说明

### 1. hover 浮窗仍然是桌面端交互

当前悬浮预览仍然只在 `hover: hover` 且 `pointer: fine` 的设备上启用。移动端缩略条仍保持点击切换，不会额外引入悬浮态。

### 2. 缩略图加载状态是运行时内存态

`loadedThumbnailUrls` 只在当前预览会话内有效：

1. 打开 viewer 后随着缩略图加载逐步填充
2. 关闭 viewer 后重新进入会重新建立
3. 这已经足够覆盖“当前轨道里这张图刚刚已经显示过”的复用场景
