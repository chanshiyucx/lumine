# 图片预览 DOM 结构整理方案

- 状态：已实施；含背景层精简
- 日期：2026-09-24
- 范围：`web/components/viewer` 的实际 DOM、各层职责和可执行的精简步骤

## 结论

当前 Viewer 的问题不是所有层都多余，而是源码按多个文件拆开后，完整的图片链路不容易一眼看清。**已加载原图的路径从对话框根节点到 `<img>`，中间有 13 个真实 DOM 容器**；其中包含 Swiper 根节点、内部 wrapper 和 slide 共 3 层、`react-zoom-pan-pinch` 生成的 2 层，以及负责原图淡入的 `m.div`。此前只比较到 `Swiper` 的层级，漏掉了这部分，不能据此判断 Lumine 的图片路径足够扁平。

已合并 4 个职责可以直接落到相邻节点的容器：轮播外的显隐容器、幻灯片内的 `ProgressivePhoto` 定位容器、信息面板内重复的 flex 容器、背景的静态裁剪容器。活动原图主路径已从 **13 个容器降到 11 个**，背景图片路径从 **4 个容器降到 3 个**。不以 DOM 数量为唯一目标；每个保留节点都应有明确的布局、测量、事件、裁剪、独立动画或库契约。

## 核对口径与改造前结构

以下是本次修改**之前**“活动照片、原图已挂载”的单条祖先路径，不是 Viewer 的 DOM 总量。`<img>` 本身不计入容器数；兄弟节点如工具栏、加载提示和缩略图不计入这条路径。React 的 `LazyMotion`、`MotionConfig`、`AnimatePresence`、`TransformWrapper` 不在这条路径上增加 DOM；`RemoveScroll` 使用 `forwardProps`，把属性转发到对话框根节点，也不额外包一层。Swiper 和 `TransformComponent` 的实际输出按仓库已安装版本核对。

```text
Viewer
  1  m.div [dialog；全屏、焦点、整体淡入淡出]
  2  div [content；图片区域 + 信息面板的布局、inert]
  3  m.div [media shell；图片舞台 + 缩略图一起随移动手势变换]
  4  section [stage；可用图片区域、手势、共享转场尺寸测量]
  5  div [carousel visibility；absolute/inset、共享转场时 opacity=0]
  6  Swiper 根 div
  7  Swiper 内部 wrapper div
  8  SwiperSlide div
  9  ProgressivePhoto 根 div [relative、size-full、overflow-hidden]
 10  m.div [原图独立淡入、完成回调、交互门控]
 11  ZoomableImage 根 div [手势事件、ResizeObserver 测量、wheel 监听]
 12  TransformComponent 的 wrapper div [缩放视口]
 13  TransformComponent 的 content div [平移/缩放、由 hook 写入内容尺寸]
      img [原图]
```

相关代码：[Viewer 布局](../../web/components/viewer/viewer.tsx#L212)、[Swiper 与幻灯片](../../web/components/viewer/photo-carousel.tsx#L52)、[缩略图/原图分支及淡入](../../web/components/viewer/progressive-photo.tsx#L107)、[缩放容器](../../web/components/viewer/zoomable-image.tsx#L62)、[缩放尺寸计算](../../web/components/viewer/hooks/use-zoomable-image.ts#L64)。这些链接指向改造后的代码；被移除的两层应通过本次 Git diff 核对。缩放库的 wrapper/content 由 `TransformComponent` 生成，不能把 `TransformWrapper` 当成第三个 DOM 节点。

未加载原图时，活动幻灯片只保留缩略图、加载提示等分支，因此路径较浅；不能用这个状态代表完整结构。`tmp/afilmory` 的 `PhotoViewer` 同样在 `SwiperSlide` 下有入场动画 `m.div`，在 `ProgressiveImage` 的原图分支里还有菜单宿主、事件转发宿主和图像渲染器节点。[对应代码](../../tmp/afilmory/apps/web/src/modules/viewer/PhotoViewer.tsx#L599)及[原图分支](../../tmp/afilmory/apps/web/src/modules/viewer/ProgressiveImage.tsx#L367)。它的顶层“背景 / 内容 / 共享转场”分区直观，值得借鉴；它不是一个可以直接照搬的更浅 DOM 模板。

## 实施后的结构

结构直接表达五种不同的职责：对话框、舞台、轮播、单张照片、缩放视口。背景、信息面板、分享弹窗、共享图片转场仍是主内容路径的兄弟分支。

```text
Viewer dialog                    焦点、滚动锁、整体进退场
├─ backdrop                      外层：移动端下拉透明度与退出动画
│  └─ backdrop-content           共享入场动画、底色、裁剪
│     └─ photo crossfade         切图时新旧照片交叉淡化
├─ content                       主区域与信息面板布局、分享时 inert
│  ├─ media shell                 移动端图片+缩略图共同变换
│  │  ├─ stage                    图片舞台、手势、尺寸测量
│  │  │  ├─ toolbar                独立控件动画
│  │  │  ├─ Swiper 根节点           同时承接轮播定位和共享过渡显隐
│  │  │  │  └─ Swiper wrapper       库内部结构
│  │  │  │     └─ SwiperSlide       同时承接单张照片的定位和裁剪
│  │  │  │        ├─ thumbnail img  原图未稳定呈现时的底图
│  │  │  │        ├─ m.div          原图淡入与交互门控
│  │  │  │        │  └─ zoom host   测量、wheel/触摸/双击入口
│  │  │  │        │     └─ transform wrapper/content → original img
│  │  │  │        ├─ loading
│  │  │  │        └─ scale indicator
│  │  │  └─ navigation            独立导航动画
│  │  └─ thumbnail rail           与舞台一起移动，但不参与舞台测量
│  └─ info panel                  桌面侧栏或移动端底部面板
├─ share dialog                  分享时独立管理焦点
└─ shared photo transition       覆盖在普通内容上方的共享图片动画
```

这里的 `zoom host` 与淡入层分开，是刻意保留的职责边界。原图淡入的完成时刻控制缩略图卸载和指针事件；缩放宿主负责 `ResizeObserver`、wheel/触摸捕获和坐标测量。为少一个 `div` 而给通用 `ZoomableImage` 增加原图加载/淡入状态参数，或把缩放 hook 移进 `ProgressivePhoto`，都会扩大模块接口、混合两类生命周期。Swiper 的 wrapper、slide 和缩放库的 wrapper/content 则是第三方库维护的布局及变换契约。

## 实施内容

### 1. 让 Swiper 根节点承接轮播显隐

移除了原先 [Viewer 中 `PhotoCarousel` 外的容器](../../web/components/viewer/viewer.tsx#L301)。`PhotoCarousel` 接受 `concealedForSharedTransition`，由 Swiper 根节点承接定位与相应 `opacity`。父组件仍依据现有 `sharedTransition` 决定何时隐藏。

这个合并不改变 `section` 的几何尺寸，也不改变 Swiper 内部 transform。运行时检查发现，Swiper 自带的 `.swiper` 规则会覆盖普通 `absolute` 类，因此根节点使用 Tailwind 的 `absolute! inset-0 size-full`，并通过 `opacity-0` / `opacity-100` 控制共享转场显隐。浏览器中验证了计算定位仍为 `absolute`、Swiper 与舞台尺寸一致，且根节点没有内联 `style`。即使在 `opacity: 0` 时也保留 Swiper 的尺寸与挂载；共享图片入场的交接依赖轮播已经就位。

### 2. 让 `SwiperSlide` 承接单张照片的定位与裁剪

把原先 [每张照片的定位容器](../../web/components/viewer/progressive-photo.tsx#L153) 合并到了 [SwiperSlide](../../web/components/viewer/photo-carousel.tsx#L89)。`ProgressivePhoto` 返回缩略图、原图淡入层、加载提示和倍率提示的同级片段；`SwiperSlide` 提供 `relative`、`h-full` 和 `overflow-hidden`。没有设置 `w-full` 去覆盖 Swiper 写入的幻灯片宽度。

缩略图和高清图都使用绝对定位，合并前后必须保持相同的定位包含块和裁剪边界。保留原图淡入 `m.div` 的 `key`、`initial/animate`、`onAnimationComplete`、指针事件门控，以及 `ZoomableImage` 的根容器和 `TransformComponent`。活动/非活动幻灯片仍共用相同的定位边界，避免切图时出现位置跳变或缩略图露边。

### 3. 合并信息面板内重复的 flex 容器

[信息面板中层 `m.div`](../../web/components/viewer/viewer-info-panel.tsx#L157) 已负责定高、flex 列布局、背景、裁剪和移动端位移；其内部原先还有一个重复建立 flex 列的普通 `div`。现在拖动提示与 `ScrollArea` 直接成为中层 `m.div` 的子节点，`min-h-0` 移到中层。桌面宽度动画仍在 `aside`，面板入场动画仍在外层 `m.div`，移动端手势位移仍在中层。

这一步不影响图片主路径；收益是信息面板结构更清楚。已在移动端检查拖动提示与滚动区域；桌面收起宽度由原有 `aside` 样式控制。

### 4. 合并背景的静态裁剪容器

按复核建议，删除了 `ViewerBackdrop` 中原先只负责定位、裁剪和禁用指针事件的普通 `div`（见此次 Git diff），把 `pointer-events-none` 和 `overflow-hidden` 移到 [已有的 `backdrop-content` 动画层](../../web/components/viewer/viewer.tsx#L245)。背景最外层继续控制移动端下拉透明度与退出动画；`backdrop-content` 继续控制共享模式的入场；每张照片的 `m.div` 继续控制切图交叉淡化。这三种独立动画仍各有一个真实节点，不能再直接合并。

背景照片路径因此从 4 层降到 3 层。运行时切图时，新旧两个带 `data-viewer-backdrop-photo` 的节点仍同时存在，`backdrop-content` 的计算样式仍为 `overflow: hidden`。

后续组件边界复核把这三层完整移进了 `ViewerBackdrop`。`Viewer` 只提供当前照片、预览状态、揭示操作编号和手势透明度；`ViewerBackdrop` 自行决定背景入退场、共享入场的 key、裁剪及切图交叉淡化。这次调整不再改变 DOM 层数，减少了背景逻辑在两个文件之间的来回跳转。浏览器复核确认背景仍为三层，切图时新旧照片节点仍同时存在。

## 保留层与暂不采用的改法

| 层或改法                                       | 决定与原因                                                                                                                                       |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `content`、`media shell`、`stage`              | 保留。`content` 布局侧栏并控制 `inert`；`media shell` 同时移动舞台和缩略图；`stage` 排除缩略图后供共享转场测量。把三者合一会改变几何与手势范围。 |
| 原图淡入 `m.div` 与 `zoom host`                | 保留。动画完成回调决定缩略图何时退场，缩放宿主有独立的事件和尺寸测量；强行合并会扩大接口并增加耦合。                                             |
| 背景的外层、按操作重建的内容层、照片交叉淡化层 | 保留。它们分别控制移动端背景透明度/退出、共享入场、切图交叉淡化；只移除了不负责独立动画的静态裁剪容器。                                          |
| 工具栏及缩略图的两层透明度容器                 | 保留。外层负责入退场，内层跟随移动端手势；两套 opacity 需要相乘，不能简单写到同一个 style/animate 属性上。                                       |
| Portal 或重排预览挂载位置                      | 不纳入。已有[历史实验](030-预览窗口图层结构优化.md)发现该改造影响照片直链的服务端预览 DOM，并已撤回。此次方案只整理当前挂载位置内部的结构。      |
| 替换 Swiper、缩放库或图片渲染方案              | 不纳入。替换库会改变手势、缩放和轮播行为，不能用来验证“去掉冗余容器”的收益。                                                                     |

## 验证与后续验收

已完成以下源码与浏览器检查。若后续修改动画或手势，仍应按相同场景回归。

1. 本地浏览器打开画廊照片后，已加载原图到对话框的祖先路径实测 11 层；Swiper 根节点的计算定位为 `absolute`，其尺寸与 `stage` 一致。活动 `SwiperSlide` 的计算定位为 `relative`，裁剪为 `hidden`。
2. 桌面端图片和信息面板正常显示；390 × 844 移动端的舞台与 Swiper 尺寸一致。移动端信息面板能展开，滚动视口高 549 px、内容高 952 px，具备溢出滚动空间。
3. 点击第二张缩略图后，活动 slide、对话框标题和路由都更新到第二张；交叉淡化期间背景内同时存在两张照片的节点。
4. `pnpm --dir web type-check`、`pnpm --dir web lint`、Prettier 与 `git diff --check` 均通过。`pnpm --dir web test` 成功退出，但当前命令发现 **0 个测试**，不能据此声称交互受到自动测试覆盖。

仍建议手动回归画廊打开、照片直链、共享与普通进退场、移动端上下滑动和放大手势、长信息滚动、分享弹窗焦点、后台标签页恢复及 reduced motion。结构精简本身不保证性能改善；如要声称性能收益，应另做相同场景的性能测量。
