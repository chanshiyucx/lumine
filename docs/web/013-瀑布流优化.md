# 瀑布流优化

## 背景

当前首页瀑布流使用的是“先按列分组，再整列渲染”的普通实现。这个方案在图片数量较少时没有问题，但随着照片数量上升，会出现几个结构性缺点：

- 所有卡片都会进入 DOM，没有虚拟化；
- 列高由本地算法一次性算完，浏览器仍要维护完整节点树；
- 滚动成本和 hover/动画成本会随图片总数线性上涨；
- 后续如果继续加筛选、排序、列表切换，会越来越难维护。

Afilmory 的参考实现位于 `docs/web/src/modules/gallery`，核心思路是：

- 使用 `masonic` 做绝对定位瀑布流；
- 只渲染可视区域附近的卡片；
- 列宽、最大列数和 overscan 作为单独配置管理；
- item 组件继续保持业务层纯展示，不掺杂布局算法。

## 实施方案

本项目没有直接照搬参考工程里那套自定义 wrapper，而是采用了等价但更轻的落地方式：

1. 引入 `masonic` 作为瀑布流虚拟化引擎；
2. 保留现有 `PhotoCard`、viewer、history 同步逻辑；
3. 将原本的 `buildMasonryLayout()` 手写布局算法移除，改为配置式 `getMasonryConfig()`；
4. 使用 `masonic` 的高层 `<Masonry>` 组件完成：
   - 绝对定位
   - 视口虚拟化
   - 滚动窗口 overscan
   - 自动测量 item 高度

## 已实施

### 1. `PhotoMasonry` 切换到虚拟瀑布流

- [photo-masonry.tsx](/Users/xin/Developer/lumine/components/gallery/photo-masonry.tsx) 现在直接使用 `masonic` 的 `<Masonry>`。
- 由于 `masonic` 在渲染阶段会依赖 `ResizeObserver`，实际接入拆成了两层：
  - [photo-masonry.tsx](/Users/xin/Developer/lumine/components/gallery/photo-masonry.tsx)：外层 client wrapper，负责 history、viewer 和 client-only 边界
  - [photo-masonry-grid.tsx](/Users/xin/Developer/lumine/components/gallery/photo-masonry-grid.tsx)：真正的虚拟瀑布流实现
- 最终没有继续使用“骨架占位 + 动态替换”的 fallback。因为那种方式会导致刷新首屏先出现错误空位，再切换成正确瀑布流。
- 当前首屏策略是：
  - 服务端先输出一个基于真实图片的静态多列流 fallback
  - 客户端 hydration 完成后再切换到 [photo-masonry-grid.tsx](/Users/xin/Developer/lumine/components/gallery/photo-masonry-grid.tsx) 的虚拟化瀑布流
- 这样可以同时满足：
  - 避开 `ResizeObserver` 的 SSR 问题
  - 刷新首屏不再显示错误骨架布局
- 当前配置：
  - `columnGutter = 4`
  - `rowGutter = 4`
  - `overscanBy = 2`
  - `scrollFps = 12`
  - `ssrWidth = 1440`
  - `ssrHeight = 900`
- `PhotoViewer`、URL history、打开/关闭切图逻辑保持不变。

### 2. 布局算法改为配置函数

- [masonry-layout.ts](/Users/xin/Developer/lumine/components/gallery/lib/masonry-layout.ts) 不再负责生成整棵列树。
- 现在它只负责：
  - `getMasonryConfig(containerWidth)`
  - `getMasonryItemHeightEstimate(photos, columnWidth)`
  - `getPhotoIndexFromPathname(pathname, slugToIndex)`
- 这让布局决策和 UI 渲染分离，后续如果要继续调列宽策略，不需要再碰主组件。

### 3. 可访问性和组件边界同步收口

- `masonic` 自身会给 item wrapper 注入 `gridcell`，所以 [photo-card.tsx](/Users/xin/Developer/lumine/components/gallery/photo-card.tsx) 里原有的重复 `role="gridcell"` 已移除。
- `PhotoCard` 仍然只负责卡片内容和交互，不负责布局容器。

## 结果

- 首页瀑布流已切到「绝对定位 + 虚拟化」架构；
- DOM 数量不再和图片总数线性绑定；
- 刷新首屏不再显示与真实照片尺寸无关的骨架块；
- 后续继续扩展照片数量、筛选条件或列表切换时，架构上更稳；
- 与 Afilmory 的核心实现方向已经对齐，但保留了当前项目自己的 viewer 和数据结构。
