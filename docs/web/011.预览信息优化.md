# 预览信息优化

## 背景

上一轮右侧信息栏已经接入了真实元数据，但在 UI 和结构上仍有几个明显问题：

1. 顶部标题区占了太多空间
2. `Artist`、`Software` 这类当前并不需要展示的字段仍然保留
3. 信息行距偏松，整体信息密度不够
4. viewer 根节点仍然给人一种右边没有完全贴住视口的感觉
5. 右侧栏只有内部区域可滚动，不是整个 `aside` 直接滚动

## 问题根因

### 1. 侧栏仍保留了单独的头部块

上一版 [components/photo/photo-viewer.tsx](/Users/xin/Developer/lumine/components/photo/photo-viewer.tsx) 右侧栏顶部仍有一整块：

1. `Photo Details` 标题
2. 照片标题
3. 相册标签

这块高度固定、信息密度低，而且会把真正的元数据内容整体往下推。

### 2. 根节点使用 `100vw`

上一版预览层根节点使用了显式：

1. `width: 100vw`
2. `height: 100dvh`

虽然理论上能铺满，但 `100vw` 在很多场景下会把滚动条宽度也算进去，因此非常容易造成“右侧多出一条空隙 / 可视偏差”的错觉。

### 3. 地点没有独立字段

当前 `manifest.json` 没有单独的 `location` 字段，但目录名里已经包含地点信息，例如：

1. `20240128-Changsha`
2. `20241116-Barmsee`

因此如果要把地点显示在拍摄时间前面，就需要从相册目录名里推导，而不是直接读取 manifest 字段。

## 已实施调整

### 1. 去掉顶部大块头部

当前 [components/photo/photo-viewer.tsx](/Users/xin/Developer/lumine/components/photo/photo-viewer.tsx) 已移除右侧栏顶部的大块 header：

1. 不再显示单独的 `Photo Details` 标题区
2. 侧栏直接从信息 section 开始
3. 信息面板的可用垂直空间明显更多

### 2. 地点插入到拍摄时间前面

当前 [lib/photos.ts](/Users/xin/Developer/lumine/lib/photos.ts) 已新增 `locationLabel`，从相册目录名推导地点：

1. 例如 `20240128-Changsha` 会生成 `Changsha`
2. 在 `Photo Info` 分组里，`Location` 已放在 `Taken At` 之前

说明：

1. 当前地点不是直接来自 manifest 字段
2. 而是从素材目录名推导出的展示值

### 3. 去掉 `Artist` / `Software`

当前右侧栏已删除：

1. `Artist`
2. `Software`

同时缺失提示区也不再报告它们。

### 4. 每行高度收紧

当前信息行和 section 间距都已经压缩：

1. 信息行从 `py-2.5` 调整为 `py-1.5`
2. label / value 行高同步收紧到 `leading-5`
3. section 从 `py-5` 调整为 `py-4`
4. 参数 chip 的内边距也同步减小

这样右侧栏整体更紧凑，更接近目标参考图。

### 5. `aside` 改为整体滚动

当前右侧栏改成了 `aside` 自身 `overflow-y-auto`：

1. 不再是“顶部固定 + 中间内部区域滚动”
2. 而是整个侧栏作为一个滚动列工作
3. 结构更简单，也更符合这个场景

### 6. viewer 根节点改回 `fixed inset-0`

为了解掉右侧残余空隙问题，当前 viewer 根节点已经去掉 `100vw` 写法，改回：

1. `fixed inset-0`
2. 由浏览器直接按视口四边贴齐

这比显式写 `100vw` 更稳，也更符合前面首页改动的同类问题结论。
