# 移动端支持

参考 Afilmory 的实现，增加移动端支持，并修复问题：

1. 修复首页瀑布流，当逐渐缩小窗口宽度，从3列变为2列，会出现2列并没有占满宽度，右边有很大的空间，而 Afilmory 不会
2. 增加移动端支持，根据屏幕宽度，需要修改预览窗口的布局，判断逻辑与 Afilmory 一致。不过 jotai 和 zustand 选一个就行，没必要使用两个。
   1. 底部略缩图的尺寸在移动端更小，参考 Afilmory
   2. 移动端的照片信息栏从右侧移动到底部，参考 Afilmory

## 实施结论

这一轮已经按 Afilmory 的方向补齐了移动端支持，并修掉了首页瀑布流在缩窄到 2 列时右侧留白的问题。

## 首页瀑布流

问题根因不是图片尺寸缺失，而是当前首页瀑布流曾经把“移动端”错误实现成了“最多 2 列”，这和 Afilmory 的 `auto` 模式并不一致。

Afilmory 的首页策略其实是：

- `< 1024px` 使用 `150px` 作为目标列宽
- `>= 1024px` 使用 `250px` 作为目标列宽
- 桌面端最多限制到 `8` 列
- 移动端并不会强行锁成 `2` 列

所以像 `820px` 这样的宽度，Afilmory 依然可以自然排出 `5` 列，而不是只有 `2` 列。

这一轮在 `components/gallery/lib/masonry-layout.ts` 中改成了更接近 Afilmory 的策略：

1. 将首页 masonry 的 auto 策略对齐到 Afilmory
2. `< 1024px` 直接使用 `150px` 目标列宽，不再限制 2 列
3. `>= 1024px` 使用 `250px` 目标列宽
4. 桌面端当列数会超过 `8` 时，动态放大列宽并把列数锁在 `8`

对应地，`components/gallery/photo-masonry-grid.tsx` 也回到了更接近 Afilmory 的 `columnWidth + maxColumnCount` 组合，而不是额外手动写死 `columnCount`。

这样当首页宽度是 `820px` 左右时，瀑布流会和 Afilmory 一样优先走 `150px` 目标列宽，自然排出 `5` 列，而不是只剩 `2` 列。

## 移动端判断

参考 Afilmory 的 `useMobile()`，当前项目没有引入 jotai 或 zustand，而是新增了轻量的 `components/gallery/hooks/use-mobile.ts`：

- 使用 `matchMedia('(max-width: 1023.98px)')`
- 与 Afilmory 的 `w < 1024` 判断保持一致
- 不额外引入全局状态库

## 预览窗口布局

预览器在 `components/gallery/photo-viewer.tsx` 中已经接入移动端布局判断：

1. 桌面端默认显示右侧信息栏
2. 移动端默认关闭信息栏
3. 移动端通过顶部 `Show Info / Hide Info` 按钮切换信息面板
4. 移动端信息面板不再出现在右侧，而是显示在主图片区和底部缩略条之间
5. 左右切换箭头仅在宽屏且具备 hover 能力时显示，触屏交互以手势和底部缩略条为主；屏幕宽度不决定是否允许触摸切图

2026-09-26 补充：预览器现位于 `web/components/viewer/`，`useMobile()` 只表示窄屏布局。宽屏 iPad 同样支持触摸切图；窄屏信息面板状态只在窄屏布局下限制滑动。当前交互规则和与 Afilmory 的差异见 [预览布局与触摸交互边界](040-预览布局与触摸交互边界.md)。

## 信息面板

`components/gallery/viewer/photo-viewer-info-panel.tsx` 现在支持两套布局：

- 桌面端：右侧固定栏
- 移动端：底部信息面板

移动端版本具备：

- 顶部 sticky 标题栏
- 独立关闭按钮
- 最大高度限制
- 垂直滚动
- 与 viewer 背景一致的毛玻璃风格

## 底部缩略图 rail

`components/gallery/viewer/photo-viewer-thumbnail-rail.tsx` 在上一轮已经虚拟化，这一轮继续对齐移动端尺寸：

- 移动端高度改为 `48px`
- 桌面端高度改为 `64px`
- 移动端最小缩略图宽度改为 `48px`
- 桌面端最小缩略图宽度保留为 `72px`

这与 Afilmory 的 `GalleryThumbnail` 里 `mobile: 48 / desktop: 64` 的策略一致。

## 其他对齐

为了让断点行为一致，这一轮还同步调整了：

- `components/gallery/viewer/photo-viewer-hover-preview.tsx`
  从 `md:block` 改为 `lg:block`
- `components/gallery/viewer/photo-viewer-info-panel.tsx`
  从 `md:flex` 改为 `lg:flex`
- `components/gallery/photo-viewer.tsx`
  顶部工具栏和桌面侧边栏切换都统一到 `lg` 断点

## 总结

这一轮的重点不是继续堆条件判断，而是把当前项目的移动端断点统一到和 Afilmory 一样的 `1024px`，然后分别处理：

1. 首页瀑布流的列宽策略
2. 预览器的信息面板布局
3. 底部缩略图 rail 的移动端尺寸

这样之后，首页和预览器在桌面端与移动端的行为就都落到了同一套断点逻辑上。
