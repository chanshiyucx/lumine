# Viewer 后台切换时的原图恢复

- 状态：已实施，待手动验证
- 日期：2026-09-24
- 范围：活动照片在标签页隐藏及重新可见时的显示与加载生命周期

## 背景

在 macOS Chrome 中，预览大尺寸 AVIF 原图时，切到其他标签页再返回可能短暂黑屏。单图隔离验证表明：只显示缩略图不会复现；标签页隐藏时卸载原图、返回后延迟挂载原图，也不会复现。这个结果证明该显示策略对当前场景有效，不把黑屏归因于某一种浏览器内部机制。

目标是在返回标签页时优先呈现缩略图，随后恢复原图；继续使用原生图片元素渲染，不引入应用层解码位图缓存。

## 放置位置

可见性监听放在 `ActiveProgressivePhoto`。它只在当前照片激活时挂载，负责决定原图加载分支是否存在；`PhotoCarousel` 继续只管理幻灯片和活动索引，无需了解浏览器标签页状态。

`ActivePhotoContent` 保留原有的下载进度、Blob URL、原图淡入、缩放及错误显示。隐藏时卸载这个内部组件，沿用 `useProgressivePhoto` 既有的取消请求与释放 Blob URL 逻辑。缩略图由外层直接显示，因此原图分支卸载期间仍有画面。

## 生命周期

1. Viewer 首次打开时先显示缩略图，并在下一轮任务中启动原有的活动照片加载流程；不增加 300 ms 首次打开延迟。
2. 收到 `visibilitychange` 且页面变为隐藏时，同步卸载原图分支、取消待执行的恢复计时器，并将缩放状态重置为未缩放。原图分支卸载会取消其加载计时器或进行中的请求，并释放 Blob URL。
3. 页面重新可见时保持缩略图，等待 300 ms 后重新挂载原图分支。原图按既有流程加载和淡入；加载完成前继续显示缩略图。
4. 如果等待期间再次切走、切换照片或关闭 Viewer，则清除计时器；已卸载的原图分支不会继续更新页面。

## 取舍

每次从后台恢复都会重新进入原图加载流程，可能再次读取 HTTP 缓存、组装 Blob 并解码图片。这里优先保证返回时有缩略图可见，不尝试固定 Chrome 的解码缓存或 GPU 纹理。原图恢复后，先前的缩放位置不会保留。

## 手动验证

1. 打开 Viewer，确认首次进入仍由缩略图过渡到原图，下载进度与淡入行为正常。
2. 在多个 Chrome 窗口中切换其他标签页，再返回 Viewer：应立即看到缩略图，随后恢复原图，没有整页黑屏。
3. 快速反复切换标签页，以及在原图加载中切走：返回后只显示当前照片，旧请求不会覆盖新画面。
4. 放大图片后切走再返回：缩放状态应重置，手势和切图交互仍可正常使用。
