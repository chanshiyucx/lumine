# 略缩图列表虚拟滚动

预览窗口底部的列缩图列表，也要实现按需加载的虚拟滚动，而不是将全部照片一起加载： components/gallery/viewer/photo-viewer-thumbnail-rail.tsx

你看一下 Afilmory 的实现，帮我优化。

## 实施结论

这一轮已经按 Afilmory 的方向完成了实现，底部缩略图 rail 不再一次性渲染全部图片，而是改成了水平虚拟滚动。

## 参考实现

Afilmory 的 viewer 缩略条在 `docs/web/src/modules/viewer/GalleryThumbnail.tsx` 中使用的是 `@tanstack/react-virtual`：

- 横向虚拟列表
- 每个 item 的宽度由 `thumbnailHeight * aspectRatio` 决定
- 当前项切换时自动滚动到容器中间
- 只渲染当前视口附近的若干张缩略图

这套方案比一次性渲染全部按钮更适合当前 viewer 底部 rail。

## 当前实现

当前项目已在 `components/gallery/viewer/photo-viewer-thumbnail-rail.tsx` 中接入 `@tanstack/react-virtual`，实现方式如下：

1. 使用 `useVirtualizer` 管理横向缩略图列表
2. item 宽度按 `aspectRatio` 和当前 rail 高度动态计算
3. 通过 `virtualizer.scrollToIndex(activeIndex, { align: 'center' })` 保持当前项居中
4. 仅渲染视口附近的缩略图项，减少 DOM 数量和图片请求压力

## 顺手清理

这轮同时清理了 viewer 中一批已经失效的冗余状态：

- 移除了 `loadedThumbnailUrls`
- 移除了 `markThumbnailLoaded`
- 移除了 `PhotoViewerThumbnailRail` 和 `PhotoViewerHoverPreview` 上未实际使用的 `onThumbnailLoad` 等多余 props
- 移除了依赖 `thumbnailRefs + scrollIntoView` 的旧居中逻辑，统一改为虚拟列表自身负责滚动定位

## 效果

优化后的底部缩略条具备这些特征：

- 大量照片时不会一次性挂出全部缩略图 DOM
- 横向滚动时只渲染当前视口附近内容
- 当前照片切换时仍能保持自动居中
- hover 预览能力保持不变
- 代码结构比旧实现更接近 Afilmory，也更适合继续扩展
