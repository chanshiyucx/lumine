# lib 目录组织与命名约定

## 文档状态

- 状态：已实施
- 日期：2026-09-22
- 范围：相册模块归拢、拍摄参数与相机标签模块重命名

## 组织原则

按实际业务职责归拢模块：照片放在 `photo/`，相册放在 `album/`，分享图片生成放在 `og/`。小型跨业务公共模块保持平铺，不为了减少根目录文件数引入 `utils/`、`shared/` 或多级技术分层。

目录名采用单数业务名；多词文件名使用 kebab-case。目录已经提供业务上下文时，文件名不重复业务前缀，例如 `album/catalog.ts`，而非 `album/album-catalog.ts`。文件名描述实际职责，避免将拍摄参数和相机标签笼统称为 metadata。

## 导入约定与依赖关系

`album/index.ts` 与 `photo/index.ts` 是包含实际基础实现的模块，不是集中重新导出所有文件的 barrel。它们不导入或重新导出服务端加载模块。

```ts
import { getAlbumDescriptor, type Album } from '@/lib/album'
import { getAlbumCatalog } from '@/lib/album/catalog'
import { getAlbumMapItems } from '@/lib/album/map'
import type { AlbumMapItem } from '@/lib/album/map'
import { getCaptureSettings } from '@/lib/photo/capture-settings'
```

服务端加载模块继续使用 `server-only`。客户端地图模块通过 `import type` 获取数据类型，通过 props 接收数据，不导入服务端加载函数。

关键运行时依赖为：

```text
album/map.ts → album/catalog.ts → photo/collection.ts → album/index.ts
```

`album/index.ts` 对 `Photo` 的引用仅为类型引用，不会反向加载照片集合。不能把 `getAlbumCatalog()` 重新导出到这个入口，否则会让基础规则间接依赖其调用方。

路由级 `_data.ts` 继续就近放在路由目录，负责具体资源查找与 404；地图交互、聚类和视口逻辑继续放在地图组件目录。本次不改变数据加载、缓存、校验、排序或展示行为。
