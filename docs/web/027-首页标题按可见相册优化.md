# 首页标题按可见相册优化

## 文档状态

- 状态：已实施
- 日期：2026-09-22
- 范围：首页瀑布流动态 header 的照片选择与更新调度

## 背景与决策

照片集合改为按拍摄时间倒序后，持续更新的相册可能与其他相册交错。此前 header 取数组中第一张仍可见的照片，即使它仅在视口顶部露出很小一部分，标题仍会由它决定。

现在按各相册照片在视口中的可见高度之和选择主要相册。所有瀑布流列等宽，因此高度之和与面积之和的排序一致，无需计算宽度或测量每张图片的 DOM。

参考了 `tmp/afilmory` 的实现：其通过瀑布流回调计算日期范围、查找地点标签，滚动位置默认约每秒更新 12 次。本项目直接复用 TanStack Virtual 的变化通知，不照搬其滚动节流，不引入日期数组排序或地点标签搜索。

## 标题选择规则

在 `web/components/gallery/lib/masonry-layout.ts` 的 `getDominantMasonryPhoto()` 中实现：

1. 可见区域排除顶部 48px header。
2. 遍历当前虚拟项，使用已有的 `start`、`end` 计算实际可见高度：

   ```text
   max(0, min(照片底部, 视口底部) - max(照片顶部, 视口顶部))
   ```

3. 忽略不可见项，按 `albumKey` 累加高度，选择总高度最大的相册。
4. 当前相册仍可见时，只有候选相册比当前相册多出超过 `有效视口高度 × 列数 × 10%` 的高度，才切换相册。这相当于按等宽列计算的视口面积差阈值，用于减少边界抖动。
5. 当前相册完全不可见时，不受切换缓冲限制；首次选择时，等量候选保留遍历中先出现的相册。
6. 日期取所选相册当前可见照片中拍摄时间最新的一张。照片集合已经按拍摄时间倒序，通过最小索引选择，无需重复解析时间或排序。

切换缓冲意味着标题在两个相册占比接近时会保留当前相册，并非每一刻都严格切换到占比最大的相册。10% 是初始体验参数，可在真实滚动体验后调整。

## 更新与性能

动态标题直接在 `photo-masonry.tsx` 的 Virtualizer `onChange` 中计算，不增加独立调度 Hook、定时器或 header 专用的 `scroll`、`scrollend`、ResizeObserver 监听。

- 当前 TanStack Virtual 的通知依赖可见索引范围和滚动状态；停止滚动默认约 150ms 后会触发状态变化通知，并使用最终位置计算标题。
- 一个简短的 layout effect 在布局就绪、照片集合或相关回调依赖变化时同步标题，避免只依赖后续滚动。
- 仅代表照片改变时向上发布；现有 header store 再按日期、相册名和显示状态去重，内容不变时不触发订阅组件更新。
- 原有瀑布流布局尺寸监听，以及 `useGalleryHeader` 控制 160px 显示阈值的监听继续保留；它们不负责重复计算相册占比。

这是精度与维护成本的取舍：同一批虚拟项内的可见占比变化，以及未触发通知的视口尺寸变化，可能要到下一次虚拟列表通知才更新标题。停止滚动的状态通知可以刷新滚动后的最终位置。延迟不保证只对应十几像素，也不声称一定肉眼无感。对于辅助标题，接受这一行为以保持单一更新来源。

不再保证每 100ms 更新一次；计算频率由虚拟列表通知决定，实际 React 标题更新仍由内容去重控制。10% 的切换缓冲继续负责减少相册边界抖动。

单次选择为 O(k + a) 时间、O(a) 额外空间，k 为当前虚拟项数量，a 为其中可见相册数量，不遍历完整图库。滚动热路径只计算数值、累加 Map，不逐张读取 DOM，不增加依赖，不引入 React 状态保存面积。

## 保留的行为

- 首页滚动超过 160px 显示日期与相册名称，回到阈值以内隐藏。2026-09-23 将阈值从 500px 缩短至 160px，使标题更早出现，接近常见布局下一行横向照片的高度。瀑布流图片高度随列宽和比例变化，该值是固定体验阈值，不代表精确的一行。
- 相册详情页继续使用固定标题，不启用动态相册选择。
- 日期格式、标题样式、瀑布流渲染、照片排序和查看器行为保持原有逻辑。
