# 地图组件性能评估与加载优化

- 日期：2026-10-18
- 状态：评估完成；第 3 节各项已实施，未提交。样式加载失败和重试未做浏览器回归
- 范围：`web/components/map/photo-map.tsx`、`web/components/map/map-markers.tsx`、`web/components/map/lib/map-clustering.ts`
- 证据口径：当前源码、已安装的 `maplibre-gl@5.24.0` 与 `react-map-gl@8.1.1`（`@vis.gl/react-maplibre`）源码、线上 manifest，以及桌面 Chromium 的 dev 页面实测。实测之外的结论标为“推断”或“待测”。没有做移动真机测试或 Performance 录制。

## 1. 结论

地图的数据量很小：线上 manifest 共 527 张照片，其中 56 张带坐标；另有 22 个相册位置，合计约 78 个点。在这个规模下，聚类计算不是流畅度问题的主要来源。

能确认的问题有三个：

- 首屏分两段加载；
- 加载阶段任何错误都会触发整页失败；
- 每跨一个整数 zoom，聚合标记都会重建。

本轮只处理这三项。毛玻璃和固定卡片的逐帧定位留待测量后再定。

dev 页面缩放时没有观察到长任务，但长任务的阈值是 50 ms，60 Hz 下一帧的预算约 16.7 ms。所以这只能说明没有严重阻塞，不能证明不掉帧，也不能证明 JS 已经可以排除。

## 3. 实施的改动

### 3.1 初始视野在创建地图时确定

**原问题**：普通入口先以 `{ longitude: 20, latitude: 42, zoom: 1 }` 创建地图，等 `onLoad` 触发后再 `fitBounds` 到主要区域。

MapLibre 的 `load` 要等 `style.loaded()` 返回真，而这需要当前视野内的瓦片全部加载完。因此遮罩先等 zoom 1 的世界瓦片，撤掉之后目标 zoom 的瓦片才开始加载。在此之前，标记也先按 zoom 1 和世界范围挂载过一次。

**改动**：

- 新增 `getInitialViewState`：
  - 有目标照片时，沿用中心点加 `FOCUSED_PHOTO_ZOOM`（15）。
  - 没有可聚焦项目时，沿用世界视野。
  - 其他情况传 `initialViewState.bounds` 和 `fitBoundsOptions`。react-map-gl 会把它们展开进 MapLibre 的构造参数，构造函数随即以 `duration: 0` 执行 `fitBounds`。
- padding 用 `window.innerWidth` 和 `window.innerHeight` 计算。地图铺满视口，组件以 `ssr: false` 加载，挂载前就能读到窗口尺寸。
- 把边界和 padding 的计算提取为 `getItemsBounds`、`getFitPadding`，首屏和“显示全部 / 恢复默认范围”共用。`fitMapToItems` 去掉只剩一种取值的 `animated` 参数，`maxZoom: 10` 提取为 `FIT_MAX_ZOOM`。
- `handleLoad` 不再移动镜头。构造阶段的镜头事件早于 react-map-gl 绑定事件，所以 `onMoveEnd` 收不到，改为在 `handleLoad` 里主动调用一次 `syncMapState`。
- `MapMarkers` 只在 `loadStatus === 'loaded'` 时渲染，避免先按 zoom 1 挂载一批标记、请求一批用不上的封面。聚类数据仍照常派生，只是不生成 DOM。

**实测**（热缓存，同一 dev 环境，改前改后各两次）：

| 版本   | 遮罩消失    | 瓦片全部加载完 | 遮罩消失后仍在补瓦片的时长 |
| ------ | ----------- | -------------- | -------------------------- |
| 改动前 | 535、534 ms | 601、632 ms    | 66、98 ms                  |
| 改动后 | 601、598 ms | 601、598 ms    | 0                          |

总完成时间基本相同；收益在于遮罩撤掉时画面已经完整。冷缓存和慢网下这段补瓦片的时间应该更长，收益也会更明显，但这是推断，没有实测。

### 3.2 只有样式加载失败才视为致命错误

**原问题**：加载阶段收到任何 MapLibre `error` 都会切到错误态。单块瓦片、sprite 或 glyph 失败时，先显示整页错误，之后 `load` 成功又切回来；如果 `load` 迟迟不来，错误遮罩会一直盖着本来可用的地图。

**改动**：

- 用 `onStyleData` 记录样式 JSON 已解析（`styleLoadedRef`）。MapLibre 在 `_load` 里解析完样式后先触发 `data`（`dataType: 'style'`），之后才会请求 sprite 和瓦片。
- `handleError` 只在加载中且样式尚未解析时切到失败。这覆盖了样式请求失败，以及 react-map-gl 创建地图时抛出的错误（例如 WebGL 不可用）。
- 样式解析之后的错误不再触发错误态，因为 sprite 失败时 `imageManager` 仍会标记为已加载，瓦片失败也不会阻止 `load`。真正卡住的加载（例如 TileJSON 失败）仍由 15 秒超时兜底。
- 重试时重置 `styleLoadedRef`。
- 判断依据是事件顺序，不解析错误文案。

### 3.3 聚类标记身份去掉 zoom

**原问题**：key 为 `${kind}-cluster-${zoom}-${minItemKey}`，每跨一个整数 zoom，所有聚合点都会卸载重挂：Marker、HoverCard 和缩略图全部重建，并重播 340 ms 的入场动画。

实测放大一级时，成员完全相同的 “Zoom into 7 photos” 聚合点也换成了新的 DOM 节点。

**改动**：key 改为 `${kind}-cluster-${minItemKey}`。同一 zoom 下各聚合的成员互不重叠，最小成员 key 仍然唯一，039 的论证依然成立。

- 跨级时，最小成员仍在的聚合点保留组件和 DOM，只更新数量、位置和预览成员。
- 其余拆出的新聚合点照常入场。

这一调整取代了 039 中“缩放级别变化时 key 变化”的验收要求。

**已知的取舍**：

- 保留下来的聚合点在 `setLngLat` 时没有过渡，会从旧中心直接跳到新中心；以前是旧点消失、新点在新位置弹出。哪种观感更好需要肉眼确认。
- 拆分或合并后，持有最小 key 的那一支会继承原组件的悬浮状态。实测“悬浮卡打开 → 点击展开”后，保留下来的节点卡片已关闭，没有残留旧内容。
- 固定的终端照片聚合 key 同样不再含 zoom。它的成员已从索引中排除，不会和索引内的聚合撞 key。

### 3.4 代码组织：只清理客户端边界声明

模块的目录结构与 Viewer 一致：平铺的 UI 文件，外加 `hooks/` 和 `lib/` 两个子目录。048 已经整理过职责划分，本轮不移动、合并或拆分文件。

**改动**：删除 `photo-map.tsx` 和 `map-markers.tsx` 中的 `'use client'`。

- `app/map/page.tsx` 只导入 `photo-map-loader.tsx`，客户端边界只需要在这个入口声明。
- 另外两个文件只被客户端模块导入：`photo-map` 由 loader 动态导入，`map-markers` 由 `photo-map` 导入。
- 规则与 [055](055-Viewer代码组织与规范整理方案.md) 第 3 项相同，不影响运行行为。

**评估后保持现状**：

| 项目                                                    | 理由                                                                                                                         |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `getMapBounds` 等镜头计算函数移到 `lib/map-viewport.ts` | 只有组件内一处使用，文件约 270 行仍可读；`getInitialViewState` 读取 `window`，返回 react-map-gl 类型，不适合放进纯逻辑文件。 |
| 聚类与首屏聚焦中构造 Supercluster 点要素的重复代码      | 每处约 6 行，泛型参数不同，抽成共用函数反而更绕。                                                                            |
| 预览相关的六个小文件归到子目录                          | 048 已决定保持平铺、三种卡片各自独立，没有新的理由。                                                                         |
| `map-config.ts`、`map-types.ts` 放在 `web/lib`          | 服务端 `map-items.ts` 和 Viewer 位置地图都在使用，放这里是对的。                                                             |
| `PhotoMap` 同时承载相册和照片，命名不够准确             | 改名要动 loader、导出和文档，收益太小。                                                                                      |
