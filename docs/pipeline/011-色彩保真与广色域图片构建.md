# 色彩保真与广色域图片构建

日期：2026-09-26

状态：已实施。

## 1. 目标与样本

在现有 AVIF + 缩略图构建中保留照片的 SDR 色彩、分辨率和细节。优先修复色彩解释错误，沿用质量 95、速度 6 和 600px / WebP 92 的配置。

从两个设备各抽查 4 张原图，读取 HEIF 主图的位深、ICC、NCLX 与辅助图像：

| 来源 | 主图信息 | 处理目标 |
| --- | --- | --- |
| Sony α6700 | 10-bit；无 ICC；NCLX primaries=1、transfer=13、matrix=5、limited range | 保留 sRGB SDR，10-bit AVIF |
| iPhone 13 Pro | 8-bit；536 字节 Display P3 ICC；无主图 NCLX；存在 Apple HDR gain map | 保留 Display P3 SDR 主图，10-bit AVIF，并保留缩略图 ICC |

Sony 样本：`DSC05903.HIF`、`DSC01862.HIF`、`DSC06061.HIF`、`DSC08059.HIF`。iPhone 样本：`IMG_4692.heic`、`IMG_5308.heic`、`IMG_5327.heic`、`IMG_5355.heic`。结论仅代表这些样本；位深本身不能用来判断 HDR。

原实现把 iPhone 的 P3 像素交给固定 sRGB 标记的 ravif，生成的 AVIF 没有 ICC；缩略图解码、重编码时也丢弃 ICC。由此造成广色域像素被按 sRGB 解释。

## 2. RGB 路径的历史

`ce236e6900991f5de2da029eda5216adab0aebba`（2026-07-20）首次引入 pipeline 时，8-bit 编码已经固定为 ravif RGB。后续模块拆分保留了该选择。

[构建优化记录](007-构建优化.md)说明，这个选择用于修复普通 JPEG 经手写 YCbCr 平面路径编码后的显示问题。提交日志没有记录更具体的根因；不能由此推导出 8-bit 图片不适合 YCbCr。

继续保留无 ICC 的 8-bit RGB 路径。带 ICC 的图片使用 libheif 的色彩转换和编码接口，避免扩展手写转换或修改 AVIF 容器字节。

## 3. AVIF 构建

源像素和源 ICC 一起保存在 `avif::LoadedImage`，由 AVIF 模块内部选择编码路径：

| 输入 | 编码路径 | 输出 |
| --- | --- | --- |
| 无 ICC、位深大于 8 | 现有 ravif 高位深路径 | 10-bit、YCbCr 4:4:4、sRGB |
| 无 ICC、8-bit | 现有 ravif RGB 路径 | 10-bit、RGB 4:4:4、sRGB |
| 带 ICC | libheif + AOM | 10-bit、YCbCr 4:4:4、嵌入源 ICC |

ICC 路径不改变 RGB 的色域，不先转换到 sRGB。8-bit 输入先按完整数值范围映射到 10-bit；高位深输入按实际源位深归一化。增加编码位深用于减少后续计算与量化损失，不会恢复源文件不存在的细节。

AOM 使用现有质量、速度、线程配置，色度固定为 4:4:4；alpha 使用相同质量。AOM 速度范围为 0–9，因此配置中的 10 在该路径取 9。两个编码器的质量、速度刻度不等价，以真实样本验证体积、耗时与像素误差。

运行环境需要 libheif 的 AOM AV1 编码器，缺失时返回明确错误。产物继续原子写入，编码失败不发布半成品。

当前无 ICC 路径面向现有 sRGB 输入；其他色域的 NCLX 输入需要另行制定色彩策略。

## 4. 缩略图与 ThumbHash

缩略图继续独立从原图生成，通过 macOS `sips` 得到已按方向处理的预览 PNG。读取预览时保留其 ICC，与像素一起传递到编码阶段。

JPEG / PNG 使用编码器的 ICC 接口；WebP 编码完成后，用 `img-parts` 嵌入预览 ICC。WebP 嵌入只修改容器元数据，不再次压缩像素。这里使用预览自身的 ICC，因为系统预览处理可能改变像素的色彩空间。

ThumbHash 从最终缩略图解码结果计算：先缩小到最长边 100px，再使用 `moxcms` 将带 ICC 的像素按相对色度意图转换到 sRGB，最后生成 hash。无 ICC 的缩略图按 sRGB 处理。首次构建和复用读取走同一条路径。

ICC 解析或占位像素转换失败时，记录包含缩略图路径的警告，使用未转换的缩小像素计算 ThumbHash。该回退仅影响加载占位的颜色近似，不修改主图、缩略图或其 ICC，也不阻断照片入库。

浏览器通过原生 `<img>` 与图片 ICC 进行色彩管理，适配屏幕色域；无需引入前端 HEIF 解码、WebGL 或 manifest 色彩字段。

## 5. HDR 边界

本次保留 iPhone 的 Display P3 **SDR 主图**，不迁移 Apple HDR gain map。因此不会保留照片在 Apple HDR 显示时的额外高光亮度。10-bit AVIF 不等于 HDR AVIF。

Apple gain map 是辅助图像及配套参数，不能作为普通 ICC 或像素附件直接复制到当前 AVIF。完整 HDR 输出需要单独验证 gain map 恢复、HDR 编码、显示端和 SDR 回退；本方案保持现有 SDR 展示链路。

## 6. 重建与模块边界

- `avif.rs` 负责源 ICC 读取、像素位深与编码路径。
- `thumbnail.rs` 负责预览 ICC、缩略图嵌入和 ThumbHash 色彩转换。
- 构建调度、state、manifest schema 和前端接口保持现有设计。

上线时删除需要修复的 iPhone AVIF 和对应缩略图，再执行构建。源文件指纹未变时，仅补建被删除的产物并更新相关 manifest 内容，不触发索尼 AVIF 全量转码。仅删除 manifest 不能修复已有图片的 ICC。

修改缩略图处理后，如希望统一给全部缩略图嵌入预览 ICC，可只删除缩略图目录重建。

## 7. 验证

使用隔离临时目录验证真实 Sony 和 iPhone 样本，不新增持久化测试代码，不执行生产图片全量重建。检查内容包括：

- AVIF 位深、色度、ICC 字节与原图一致性，以及解码后的像素误差。
- Sony AVIF 与修改前产物的一致性。
- JPEG / PNG / WebP 缩略图 ICC，首次构建与复用的 ThumbHash 一致性。
- 样本编码体积与耗时，Rust 格式、严格 Clippy 和 release 编译。
- 非交互运行时，编码失败原因仍写入 stderr，不被隐藏的进度条吞掉。

### 实测结果

同机 release 构建，配置保持 AVIF 95 / 6、WebP 92 / 600px。两张 iPhone 同批处理：原路径 12.5s，新路径 6.6s；该结果仅代表这次样本与本机 AOM 3.14.1。

| 样本 | AVIF 字节数：原 → 新 | RGB PSNR：原 → 新 | 输出 ICC |
| --- | --- | --- | --- |
| `DSC05903.HIF` | 15,179,982 → 15,179,982 | 43.94 → 43.94 dB | 无 ICC，sRGB NCLX 不变 |
| `IMG_4692.heic` | 2,354,435 → 2,683,410（+14.0%） | 49.65 → 52.20 dB | 与原图 536 字节 ICC 完全一致 |
| `IMG_5308.heic` | 3,781,170 → 4,141,185（+9.5%） | 48.31 → 50.42 dB | 与原图 536 字节 ICC 完全一致 |

PSNR 以 libheif 解码后的 8-bit RGB 主图为参照，衡量重编码的数值误差，不代表 HDR 保真或完整的主观画质评价。原路径的 P3 色彩标记错误不体现在这个数值中。

另用临时 16-bit RGB 和带 alpha 的 8-bit RGBA 输入验证 ICC 编码路径，输出均为 10-bit / 4:4:4，alpha 正确保留。

Sony 样本 AVIF 逐字节一致。两张 iPhone 的 WebP 缩略图各增加 562 字节；JPEG / PNG / WebP 均可重新读取正确 ICC，各格式首次构建与复用的照片条目和 ThumbHash 一致。

### Sony range 复核

对 `20241116-Barmsee/DSC02472.HIF` 仅切换 libheif 的 `autocorrect_broken_input`，10-bit RGB 均值从 `(323.73, 290.41, 237.92)` 变为 `(361.67, 331.45, 279.07)`。

按 `sips` 预览的 EXIF 方向将两种结果对齐，再与完整 `sips` 解码一起缩小到 600×400，默认解码的平均 RGB 绝对误差为 7.38，开启修正为 9.73（8-bit 数值尺度）。这能证明解码行为有差异，不能证明开启修正后与系统显示一致。当前保留默认解码，后续调整需有可信色彩参考。

旋转样本的源 EXIF 未包含 Orientation；容器为 90° 旋转。`sips` 预览以 900×600 像素和 EXIF Orientation=8 保存，现有预览解码正确生成 600×900 缩略图，保持当前方向处理。

### 占位转换失败复核

临时灰度 PNG 嵌入系统 Generic Gray Gamma 2.2 ICC，可复现 `Invalid layout` 导致照片处理失败。优化后转换失败只输出警告，仍生成 ThumbHash 并完成照片条目。正常 Display P3 和无 ICC 路径的图片、占位结果保持不变。
