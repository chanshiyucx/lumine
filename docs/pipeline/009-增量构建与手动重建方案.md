# 增量构建与手动重建方案

日期：2026-09-26

状态：已实施。

## 1. 文件职责

| 对象 | 职责 |
| --- | --- |
| 源照片 | 提供图片内容、EXIF、显示尺寸、方向和源色深 |
| `state.json` | 记录上次成功处理的源文件指纹，判断源照片更新 |
| 全尺寸 AVIF | 从源照片生成的全尺寸图片产物 |
| 缩略图 | 从源照片生成的预览图片产物 |
| `manifest.json` | 保存供 Web 使用的照片元数据、资源描述和 `thumbHash` |

AVIF 与缩略图独立生成、独立复用。manifest 条目独立更新，其缺失或格式变化只触发信息重建。

## 2. state.json

```json
{
  "files": {
    "20260920-Munich/DSC08145.HIF": {
      "size": 8432190,
      "mtimeMs": 1790001401000
    }
  }
}
```

| 字段 | 定义 |
| --- | --- |
| `files` 的键 | 相对于 `sourcePath` 的完整源文件路径，保留扩展名，以 `/` 分隔 |
| `size` | 上次成功处理时的源文件字节数 |
| `mtimeMs` | 上次成功处理时的源文件修改时间，Unix 毫秒整数 |

每张照片的产物与条目处理成功后，才保存其当前指纹。失败时保留旧记录。

## 3. 更新判断与图片复用

每次构建扫描源文件并应用 Finder 标签筛选，然后比较 state：

- `unchanged`：已有记录，大小和修改时间均相同。
- `changed`：已有记录，大小或修改时间不同。
- `untracked`：没有记录，建立新的状态基线。

| 源文件状态 | 图片处理 |
| --- | --- |
| unchanged | 分别复用可用的 AVIF 和缩略图，补齐缺失或损坏的产物 |
| changed | 重建该照片的 AVIF 和缩略图 |
| untracked | 接纳现有可用产物，补齐缺失产物，成功后记录当前指纹 |

常规复用检查预期路径存在非空普通文件，并与已有资源描述核对路径、格式和字节数。描述缺失或字节数变化时，从实际文件读取资源信息；缩略图同时重新计算 `thumbHash`。确认损坏的图片重新生成。

state 缺失时按 untracked 处理；state 损坏时报告错误，维护者删除后重新建立基线。基线恢复采用现有产物，因此源文件曾变化且历史 state 丢失时，需要手动删除相关图片以确保重新生成。

更新判断采用大小和毫秒修改时间。保持两者不变的源内容替换，由维护者手动删除对应产物及 manifest 后刷新。同一输出目录对应固定的源目录。

## 4. 图片生成

```text
源照片
  └─ 按需读取源信息：显示尺寸、方向、源色深
       ├─ AVIF 生成
       └─ 缩略图生成
```

两个生成函数共享必要的源信息，各自输出资源描述。执行顺序由并发和内存控制安排。

缩略图宽度为 `min(源照片显示宽度, 配置缩略图宽度)`，保持比例。显示尺寸按 EXIF 方向和 HEIF 容器变换计算。

仅生成缩略图时，从源照片取得尺寸与预览像素；仅生成 AVIF 时保留已有缩略图。两者都需要生成时，保留现有全分辨率任务限流。

## 5. manifest 更新

| 情况 | 条目处理 |
| --- | --- |
| unchanged，产物完整且条目有效 | 复用整条 |
| 新增、changed 或 untracked | 读取源元数据，结合实际产物生成完整条目 |
| 只重建 AVIF | 更新 AVIF 资源描述，保留其他字段 |
| 只重建缩略图 | 更新缩略图资源描述和 `thumbHash`，保留其他字段 |
| 缺少有效条目 | 从源照片和现有产物重建完整条目 |
| 照片退出筛选集合 | 移除条目 |

用预期 AVIF 相对路径匹配当前 schema 的旧条目，各资源描述分别核对预期路径。manifest 缺失或版本不符时重建全部条目；JSON 损坏时报告错误，删除后重建。

重新生成条目时：

- 从源照片读取并归一化 EXIF，按需探测源尺寸和源色深。
- 从实际图片产物取得 `url`、`width`、`height`、`bytes`、`mime`。
- 从编码后的实际缩略图计算 `thumbHash`。

摄影字段遵循 [manifest v3 字段规范](../web/043-照片元数据字段规范与manifest-v3.md)。源色深保留在源信息读取及编码逻辑中；可选源色深无法低成本探测时省略。

合并复用条目与更新条目，按固定顺序保存。集合或条目有变化时写入 manifest 并更新 `updatedAt`；完全无变化时保持 manifest 和 state 文件不变。

CLI 的 `to process` 和 `processed` 按照片任务计数，包含仅重建元数据的任务；`reused` 表示完整复用照片条目。

## 6. 构建流程

统一使用 `pipeline/build.sh`：

1. 校验配置、源目录与输出目录隔离关系。
2. 完整扫描源文件，应用标签筛选，取得指纹。
3. 计算两类产物路径，检查路径碰撞。
4. 读取 state 和 manifest，分别决定图片生成范围与条目更新范围。
5. 按需读取源信息，独立生成或复用 AVIF、缩略图，完成照片条目。
6. 处理后再次核对源指纹，稳定且全部成功才更新该照片的 state。
7. 保存成功条目及状态，完成后清理退出图库的产物。

沿用源相对目录和替换扩展名规则。例如 `album/DSC08145.HIF` 对应 `gallery/album/DSC08145.avif` 和 `thumbnails/album/DSC08145.webp`。路径碰撞在写入前报错。

### 保存与恢复

图片和 JSON 通过临时文件写入后原子替换。checkpoint 先保存包含复用条目的 manifest，再保存 state；内容未变化的文件保持不变。

失败照片保留旧指纹，排除于本次 manifest，输出失败列表并返回非零退出码。下次构建仍能识别已知的源变化。新照片处理期间发生源变化时，移除本次为它生成的产物。

构建由单个本地进程执行，期间保持源照片稳定，完成后发布产物。

### 清理

完整扫描且本轮全部处理成功后，先移除退出集合的 state 记录并保存最终 manifest 和 state，再比较预期路径集合与两个专用图片目录，清理退出集合的管线图片。

源文件删除、重命名、取消筛选标签和缩略图格式变化，都按当前预期集合处理。清理限制在配置的图片目录内；目录配置变更后，旧目录由维护者处理。

## 7. 手动重建

路径相对于 `targetPath`，当前 AVIF 目录为 `gallery/`，缩略图目录为 `thumbnails/`。删除对应产物后运行同一个构建入口。

| 目的 | 操作 | 结果 |
| --- | --- | --- |
| 新增或更新源照片 | 添加或正常修改源文件 | 自动处理新增或变化照片 |
| 更新元数据提取、manifest 字段或 hash 算法 | 删除 manifest | 重建全部条目，复用图片 |
| 更新 AVIF 编码或参数 | 删除指定 AVIF 或 `gallery/` | 重建对应 AVIF，复用缩略图 |
| 更新缩略图处理或参数 | 删除指定缩略图或 `thumbnails/` | 重建对应缩略图，复用 AVIF |
| 更新两类图片共有的处理逻辑 | 删除两类相关图片 | 重建两类图片 |
| 恢复 state | 删除 state 后构建 | 保留可用产物，建立当前基线 |
| 全量重建 | 删除两类图片目录、manifest 和 state | 生成全部产物与状态 |

修改编码参数后，已有产物由手动删除来刷新，新产物使用当前参数。源照片指纹变化时，自动重建两类图片。

## 8. 实施与验收

构建策略集中在 `build.rs`，源信息、元数据、图片处理和保存实现按 [构建管线模块拆分](010-构建管线模块拆分.md) 分工：

- 精简 state 为源指纹。
- 分离源更新判断、图片复用和 manifest 条目复用。
- 提供按需读取的源信息，解耦两个图片生成函数。
- 支持读取现有产物描述、增量更新 manifest 和成功后保存 state。
- 按完整成功的当前集合清理产物。
- 同步 README 和相关数据格式文档。

在隔离临时目录验证以下行为：

| 场景 | 预期 |
| --- | --- |
| 无变化再构建 | 图片和 JSON 均保持不变，复用元数据与 hash |
| 删除或更新 manifest schema | 重建条目，图片保持不变 |
| 单独删除任一类图片 | 只重建该类，更新对应描述 |
| 更新一个源文件 | 只重建该照片的两类图片及条目 |
| 删除 state | 复用可用图片，建立指纹基线 |
| 处理失败或中断 | 保留旧指纹，下一次继续处理 |
| 源文件退出集合 | 成功后移除条目、状态和旧产物 |
| 扫描或处理失败 | 返回错误，保留未清理产物 |
| 路径碰撞 | 写入前报错 |
| 高位深与旋转样本 | 显示尺寸、方向、颜色正确，首次生成与复用的 hash 一致 |

验证图片是否复用时核对文件字节和修改时间。
